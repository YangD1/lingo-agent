# 0048 · 出题按题并行，过审的题先显示

- **状态**：已采纳（2026-10-16，任务 89.3、89.4；方向由用户选定：按题并行 + 设置页可换快模型）
- **日期**：2026-10-16
- **影响**：修订 ADR 0021 §3（出题图）、ADR 0044 §4（测验卡片等整组出完）。`agents/exercise_graph.py` 重写为按题位的流水线；`rules.yaml` 的 `practice` 一节新增 `parallel_calls`；过审的题立刻存库；题组在 `generating` 时也能作答；`/practice/sets/{id}` 新增 `planned`；练习页和测验卡片先显示已就绪的题。无迁移。

## 背景
- 实测（任务 89.1，百炼 qwen-plus，测验 5 题）：从卡片出现到能作答约 57 秒。其中出题一次调用 30 秒（输出 1319 token），审题一次调用 17 秒，重写被拒的题 7 秒。开发库里用 DeepSeek-V4-Flash 出题平均 33 秒，审题约 15 秒。
- 慢在流程上：所有题位一次调用写完，再一次调用审完，被拒的题位整体再来一轮；前端要等整组状态离开 `generating` 才显示第一题。一次结构化输出的耗时大致和输出长度成正比，5 道题要等 5 道题的输出时间。
- 用户的设想是“预设组件、AI 只填内容”。题型组件和数据结构本来就是预设的（ADR 0021 §2、任务 86.9），所以这次改的是流程，不是题型。

## 决定

### 1. 每个题位一条流水线，并行跑
- 每个题位独立走“出题（只写这一道）→ 代码校验 → 审题（只审这一道）→ 判定”。被拒或校验不过时，带着原因重写这一道，最多 `1 + practice.max_regenerations` 轮，和以前一样。
- 各题位并发执行，同时进行的模型调用不超过 `practice.parallel_calls`（4），防止一组 10 道题同时打 20 个请求。
- 复用现有的提示词装配（`generate_messages`、`critic_messages`、`generated_set_model` 本来就接受题位列表，现在每次只传一个），提示词内容不变。
- 等待预算（任务 49.3）按题位判断：一个题位按它上一轮的耗时估算，如果开新一轮会超出整组的预算，就不再开，这个题位交给题库补。
- 模型调用失败只结束这一个题位，其他题位继续。`NoModelConfiguredError`（没配模型、额度用完）会让所有题位都不再开新调用。
- 阶段（`stage`）：开始时是 `generating`；任何一个题位进入第 2 轮后是 `rewriting`；补题库时是 `filling`。`reviewing` 不再上报，因为各题位的阶段不同步。

### 2. 过审的题立刻存库，题组仍是 `generating`
- 一道题过审后，马上写一行 `exercises`（`status = ok`）。题组状态不变，接口照常返回已存的题，按 `position` 排序，中间可能有空缺（还没出完的题位）。
- 全部题位结束后，`fill` 用题库补空缺，`save_result` 只插入还没存过的题（按 `position` 去重）、被拒的草稿，然后改题组状态。
- 进程中途退出时：已经存了的题保留，题组照旧被服务标成 `failed`（ADR 0021 §3）。

### 3. 出题过程中就能作答
- `generating` 的题组里已存的题可以作答（`answer.OPEN_SET` 加上 `generating`）。
- 第一次作答时记录“作答前的掌握度”（Q35c）。这时还有题没出来，所以按计划里的语法点（`kc_plan`）记，而不是按已有的题记。题组状态仍是 `generating`。
- 出题结束时：
  - 已经开始作答的题组（有 `mastery_before`）变成 `in_progress`，否则变成 `ready`。题库补进来的、计划外的语法点（`wider_kcs`）在这时补记作答前的掌握度：这组题还没碰过它们，此时的值就是作答前的值。
  - 如果这时所有题都已作答，题组直接变成 `done`。练习页的“提前生成下一组”也在这里触发（以前只在作答接口里触发）。
- 题太少（少于 `min_items`）时：还没开始作答就照旧 `failed`；已经开始作答的不判失败，用已有的题收尾。学习者已经在做的题不应该消失。

### 4. 接口
- `SetOut.planned`：计划的题数（`kc_plan` 的长度；计划排好之前是 0）。出题过程中，前端用它显示“第 n / 共 N 题”。出完以后，以实际题数为准（被丢掉的题位会让题数变少）。

### 5. 前端
- 练习页、测验卡片：只要有一道已就绪、还没作答的题就显示出来，`generating` 时继续轮询。作答完已显示的题、后面的还在出时，显示“正在出下一题”和当前阶段。
- 测验卡片的小结、练习页的总结只在题组离开 `generating`、而且没有待作答的题时出现。

### 6. 代价
- 每道题单独调用，系统提示和学习者信息每次都要发一遍。按 89.1 的数据估算，5 道题的测验，输入 token 从约 6.6k 涨到约 18k，输出不变。百炼、DeepSeek 等有隐式前缀缓存，重复的部分会便宜一些。`features.yaml` 的估计按实测更新（任务 89.5）。
- 换来的是：第一道题大约在“一道题的出题 + 审题”时间后出现，整组的耗时接近最慢的那一道，而不是所有题输出时间的总和。

## 后果
- 出题图从“整组的轮次”变成“题位的轮次”，`ExerciseState` 不再按轮次推进，图只剩 `produce → fill → save` 三个节点。
- 被拒、校验不过的原因仍然写进 `exercises.critic`（被拒的题）和日志，评估集照旧可以用。
