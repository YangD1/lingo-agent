# 0029 · 口语练习：情景、speaking_coach 与口语证据

- **状态**：已采纳（2026-10-09，任务 52；P3 计划 Q4–Q6 由用户确认，全部按推荐）
- **日期**：2026-10-09
- **影响**：新增 `backend/app/speaking/`（情景清单）、`speaking_coach` 子图和 Supervisor 路由；`conversations.purpose` 新增 `speaking` / `realtime`，加列 `scenario_id`；新增表 `speaking_sessions`；`kc_evidence.source` 加 `speaking`；新增结构化调用 `speaking_summary`；新页面 `/speaking`；每日计划（ADR 0027）加可选项“口语”。ADR 0030 的实时语音复用这里的情景、证据和小结。

## 背景
- PLAN 的“语音”需求有“情景口语角色扮演（面试、点餐、会议）”，P3 模式 A 是“ASR → LangGraph → TTS”的半双工口语练习。
- 现有基础：语音消息转写（ADR 0008，录音 → 转写回填输入框）、朗读三层（ADR 0018 / 0028）、Supervisor 按确定信号路由到 coach（ADR 0023）、反思打标把对话里的错误记成证据（ADR 0012）。
- 口语和打字聊天的差别：回复要短、节奏快；转写可能出错，不能把转写错误算到学习者头上；每轮纠错会打断表达。

## 决定

### 1. 情景
- `backend/app/speaking/scenarios.yaml`：id、标题（中英）、等级范围、私教扮演的角色、学习者的目标、开场要点、可选的目标表达。首批 8–10 个：自我介绍 / 面试、点餐、问路、酒店入住、看病、开会发言、电话预约、聊兴趣爱好；另有“自由聊”。启动时加载并校验，和 `grammar.yaml` 一样是代码仓库里的文件。
- 列表按学习者等级排序和过滤（等级范围外的折叠显示）。

### 2. 会话与路由
- 口语会话是 `conversations.purpose = speaking`，新列 `scenario_id`（可空，“自由聊”为空）。Supervisor 按 purpose 确定路由到 `speaking_coach`，不调分类（ADR 0023 §3）。
- `speaking_coach` 子图沿用 tutor 的 load_context（画像、记忆、学习者模型），加情景设定；提示词 `prompts/speaking_coach.md`。
- 回复约束：短（`rules.yaml` 给每个等级的句数上限）、按等级控制词汇和句长、每轮以一个问题或接话结尾推动对话。
- **纠错方式（Q4）**：对话中不打断，只在说错影响理解或是高频错误时用复述（recast）自然带出正确说法；错误集中到结束小结里讲。

### 3. 语音回合（半双工）
- 按住说话（手机）或点一下开始、再点结束（桌面）→ 现有 `asr` 转写 → 直接作为学习者消息发送（口语会话里不回填输入框等确认；转写结果在气泡里显示，可以点“改一下”修正后重发）→ 回复流式生成 → 按句流式朗读（ADR 0028 的三层）。
- 随时可以切换成打字。没配 `asr` 时口语页只能打字，并引导去设置页。

### 4. 证据（Q5）
- 学习者的话语照常走反思打标，`kc_evidence.source = speaking`，算“产出”证据（ADR 0010 的 produce）。
- 转写不可靠的话语不记错误证据：少于 3 个词的，或转写返回了置信度且低于阈值的（阈值放 `rules.yaml`）；记“用对了”的证据不受影响。学习者手动改过的转写按改后的文本算。
- 口语能力估计（`skill_estimates.speaking`）除了跟读分（ADR 0028 §6），还按小结里的可理解度评级更新（结构化输出给出等级，代码换算，不让 LLM 直接打分数）。

### 5. 小结
- 学习者点“结束”（或离开超过 30 分钟后下次打开时）生成一次 `speaking_summary` 结构化调用：说得好的地方、错误与改法（引用原话）、更地道的说法、下次可以练的表达、可理解度评级。
- 存 `speaking_sessions`（user、conversation、scenario、开始 / 结束时间、轮数、说话秒数、summary JSONB、来源 cascade / realtime）。小结里的表达可一键加生词本、一键跟读（ADR 0028 §6）。
- 小结的错误不重复记证据（反思已经记过），只做展示。

### 6. 入口
- 新页面 `/speaking`：情景列表、继续上次、历史小结；实时语音（ADR 0030）配好了时，情景卡片上多一个“打电话”按钮。
- 看板“今天”私教可以给口语卡片；每日计划加可选项“口语 10 分钟”（Q6），默认不勾，学习者在确认卡上自己加；完成情况按当天口语会话的说话时长现算（ADR 0027）。

### 7. 公示
- `features.yaml`：`speaking_turn`（`speaking_coach` 的回复 + `asr` 转写 + 可选 `tts`）、`speaking_summary`；口语页入口和“结束并生成小结”按钮挂 `AiBadge`。
- `docs/agent-tools.md`：speaking_coach 路由、小结调用；回复下的“私教做了什么”和普通对话一样展示。

## 取舍
- **口语会话转写直接发送**：语音聊天的节奏比准确更重要；转写错了可以改，改后的文本才计证据。
- **recast 而不是逐句纠错**：逐句纠错会让学习者不敢开口；代价是对话中的反馈少，所以小结要讲清楚。
- **按话语长度和置信度过滤证据**：会漏掉一些真错误，但宁可少记，也不能把转写错误记成学习者的错（掌握度会被拉低，选题跟着跑偏）。
- **情景放 YAML 不放数据库**：和语法清单一样，便于审阅和开源贡献；学习者自定义情景以后再说。

## 落地记录（任务 59，2026-10-10）

页面完成，Q59a–h 按推荐确认。和上文的差别、补充：

- **流式朗读**（59.1）：`lib/speech.ts` `speakStream(owner)`，边收回复边按句排队朗读，复用服务端朗读和浏览器兜底；句号后面要有空格才算句末，末尾的句号等后文；被打断后再来的文字不读。Safari 要求在点击里解锁播放器，所以发送和松开说话按钮时先 `unlockSpeech()`。
- **列表页**（59.2）：`/speaking`：继续上次（最近一个进行中的）、自由聊 + 合适等级的情景（其他等级折叠）、练过的（说了几分钟、可理解度、删除）。同一情景再开就新开一次，不限一个进行中（Q59h）。没配转写时说明只能打字。导航“学习”组加“口语”。
- **会话页**（59.3–59.4）：一个麦克风按钮：按住说、松开发；按下不到 0.3 秒算点一下，再点一下发送；移出按钮松开取消；桌面按住空格说；单次最长 60 秒；开始录音先停朗读（Q59a）。转写后直接发送，转写中显示占位，空转写提示没听清、不发送，失败可重试或改打字（Q59b）。只有最后一条没改过的语音消息能“改一下”，原地编辑后作为新消息发送，原消息划掉并标“已改”（Q59c）。默认自动朗读、显示回复文字，两个开关都存在浏览器（Q59e、Q59f）。
- **小结**（59.5）：结束后同一页显示小结：说错的（原话 → 改法）、更地道的说法、下次可以试的，改法和表达都能跟读（跟读 source `speaking`），表达能加入生词本；小结失败可重试；“再练一次”同情景新开。
