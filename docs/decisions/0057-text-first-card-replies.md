# 0057 · 先说话、同一条回复给卡片，只给快捷卡片时不再调第二次模型

- **状态**：已采纳（2026-10-20，任务 114.2；用户确认拆法和顺序）
- **日期**：2026-10-20
- **影响**：**补充 ADR 0015 §1、§5**（工具循环、`done` 的 `message_id`）。tutor 子图 `tools` 节点后的边改成条件边；提示词 `tutor_tools.md` 改“先写文字再调工具”。无迁移，SSE 事件和历史接口格式不变。

## 背景
任务 114 实测（sub2api gpt-6-sol，桌宠每天第一次开场）：模型第一次调用只出卡片工具、没有文字，文字要等工具执行完再调一次模型才开始写。学习者先看到卡片，过 5 s 以上才看到第一个字；普通对话里带卡片的回复同样是两次调用（约 4.7 s + 4.3 s）。

`suggest_link` / `suggest_practice` 的工具结果只有“卡片已显示”，没有需要转告学习者的东西，第二次调用通常只是补一句“点卡片开始”。

## 决定

### 1. 提示词：先写给学习者的话，再在同一条回复里调工具
- `tutor_tools.md`：要给卡片时，先把要说的话（建议和理由）写完，再在同一条回复里调工具。只给快捷卡片时，这就是整条回复。
- 流式代码不变：第一次调用里的文字本来就逐字推送（ADR 0015 §5），所以第一个字的时间 ≈ 首包时间。

### 2. 图：`tools` 之后按情况结束
- `tools` 节点后改成条件边 `after_tools`：刚执行的那条 AI 消息**有文字**，且它的工具调用**全是 `suggest_link` / `suggest_practice` 并都成功**，就结束这一轮；否则照旧回到 `tutor`。
- 照旧再调一次的情况：
  - 有调用失败（范围外、参数错、超出每次 3 个），模型要改正或换一个；
  - 结果里有要转告的内容：`give_quiz`（续上未完成的那组等）、`suggest_lesson`（锁住时换成最早能学的那课）、工作区工具、`propose_*`、`withdraw_card`、`load_skill`；
  - 模型没写文字，只出了工具调用（有的厂商就是这样）：退回原来的两次调用，不会比现在慢。
- 这一轮以 `ToolMessage` 结尾：下一轮学习者的消息直接接在后面，OpenAI 兼容接口、Anthropic、DeepSeek 都接受。
- `done.message_id` 仍取这一轮最后一条 AI 消息的 id（就是带卡片的那条）；历史接口照旧合并、去掉工具消息。

## 取舍
- **只放行两种快捷卡片**：它们的结果没有新信息，结束不会让学习者漏掉什么；其余工具的结果可能改变该说的话，宁可多等一次调用。
- **不强制要求文字在前**：模型不照做时自动退回原流程，正确性不受影响，只是没提速。
- **代价**：模型说话时还不知道卡片是否成功；失败时第二次调用会改正，学习者可能先看到“点下面的卡片”再看到改正。范围内的卡片在 114.1 之后基本不会失败。
