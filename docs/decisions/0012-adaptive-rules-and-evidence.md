# 0012 · 自适应规则可配置、证据可重算、题目难度的分工

- **状态**：已采纳（2026-09-29，任务 7 开工前和用户确认）
- **日期**：2026-09-29
- **影响**：新增 `backend/app/adaptive/rules.yaml`（带版本号，启动时校验）；ADR 0010 的 `mistakes` 表改为 `kc_evidence`（所有观测，只追加）；`kc_mastery` 变成可重算的缓存并记下规则版本；入学测题目难度由“LLM 按维度打分给先验 + Elo 按作答校准”共同决定。

## 背景
ADR 0010 定了 BKT、Elo 的分工和默认参数，但这些参数、先验、“哪些错误算观测”之类的规则都是初值：真实使用之后一定会改。如果规则写死在代码里、掌握度只存一个随证据累加的数，那么每次改规则都要改代码，并且已有用户的掌握度是按旧规则算的，无法和新规则对齐。

另一个问题是题目难度：用户认为 LLM 分析难度是必要的，但需要一个标准来界定 LLM 和算法各管什么。

## 决定

### 1. 规则集中在一个带版本号的配置文件里
`backend/app/adaptive/rules.yaml`（进仓库）用 Pydantic 校验，启动时加载，出错拒绝启动。包含：
- BKT：`p_learn`、`p_slip`、识别证据和产出证据各自的 `p_guess`、达标阈值、先验表（已知学习者等级时按等级差给值；未知时按 KC 等级给值）。
- 证据策略：哪些严重度作为 BKT 观测（初值：low 只记录不计入）；同一轮对同一 KC 最多计几次观测（初值 1）。
- Elo：`α`、`β`（`K(n) = α/(1+β·n)`，学习者和题目共用形式、参数分开）、四选一的猜测下限。
- 题目难度评分标准：各维度的取值和系数（见第 3 条）。
- `version`：规则的任何改动都要改版本号。

算法代码只读规则，不含任何魔法数。改规则 = 改 YAML + 改版本号 + 跑单测。

### 2. 证据是原始记录，掌握度是缓存
- **`kc_evidence`**（只追加）：每条观测一行，包括对话里的错误和用对、入学测作答。字段：user_id、kc_id、`correct`、`evidence`（recognition / production）、`source`（chat / placement）、conversation_id（会话删除时置空）、message_id、created_at；错误行另有 error_type、severity、original、correction、l1_transfer。**看板和学习者模型页的“错误”就是 `correct = false` 的行**。
- **`kc_mastery`**：每人每 KC 一行，存 p_mastery、观测计数、`rules_version`。它可以由证据按时间顺序重放算出：规则版本变了，就用新规则重放该用户的证据（重放是纯函数，任务 8 接入触发时机）。
- 严重度过滤、每轮去重这些规则在**重放时**生效，而不是在写入时丢弃证据，所以改了这些规则，旧证据也能按新规则重新计算。

### 3. 题目难度：LLM 给先验，算法做校准
难度分成两部分，按“理解 vs 记账”划界：

| | 先验难度（还没有人作答） | 实测难度（有作答之后） |
|---|---|---|
| 需要的能力 | 理解题目：读题干、判断干扰项的迷惑度 | 记账：作答结果与预期的差 |
| 谁来做 | LLM，按评分标准分维度打分 | Elo，按作答更新 |

- **LLM 不直接给难度数字**，而是按维度打分（结构化输出，每个维度附理由）：目标 KC 的 CEFR 等级（直接取清单，不由 LLM 判断）、词汇难度、句法复杂度、提示线索、干扰项迷惑度。难度 = 等级基准 + 各维度加减分，系数在 `rules.yaml` 里。维度分和理由都存下来，便于审核和回头调系数。
- **Elo 校准**：每道题存 difficulty 和 attempts，初值为先验难度；作答后按题目自己的 `K(n)` 更新，作答越多越稳定，先验的影响自然淡出。
- **防噪声**：入学测过程中学习者能力值还不准，不用它更新题目；测完后用最终能力估计统一回算这一轮的题目更新。
- 落地顺序：任务 7 写纯函数（题目更新、维度分 → 难度）；任务 14 题库按此标准打分并人工审核；任务 15 建题目统计表并接入测后回算；P2 的练习生成沿用同一标准，由 critic 核对。

## 取舍
- **重放的成本**：一个用户的证据是千条量级，重放是毫秒级的纯计算，只在规则版本变化或用户删除证据时触发，可以接受。代价是 `kc_evidence` 只追加、会一直增长，P4 再考虑归档。
- **规则放仓库还是按租户配置**：P1 放仓库，全站统一；按租户覆盖规则等有真实需求再做。
- **不让 LLM 看作答数据调难度**：那样难度会随 LLM 的判断漂移、不可复现，和“LLM 不给掌握度打分”是同一条原则。
