# 0016 · 对话式学习建议

- **状态**：已采纳（2026-10-01；Q23a–Q23g 和补充细节都由用户确认）
- **日期**：2026-10-01
- **影响**：修订 P1 计划 §7.5 的“今天的建议”流水线（模型写理由、`learning_advice` 缓存、刷新接口都去掉）和 ADR 0015 §6（规划对话从跳转改为嵌在结果页里）。`conversations.purpose` 新增 `daily`；`features.yaml` 去掉 `advice`。ADR 0013 的工具规范、ADR 0015 的卡片机制都不变。

## 背景
P1 实测反馈：看板的“今天的建议”和入学测结果页的建议列表“太僵硬、太呆板”。它们是一张静态卡片：算法挑候选，模型写一句理由，学习者只能点链接。用户的意见是，这里应该直接放一个和私教对话的组件，“chat 交互感才是 agent 应用的灵魂”。

现有的零件已经够用：
- 规划对话（ADR 0015 §6）每轮都把算法候选、最近一次入学测和错题语法点放进 system prompt，卡片范围也由这些候选限定。
- 私教工具能出提议卡（换词书、设目标，确认后执行、可撤销）和直达卡（练习、复习、筛词、重测）。
缺的只是：对话不能嵌在看板和结果页里，而且看板没有对应的会话。

用户已确认（2026-10-01）：
- Q23a：看板和入学测结果页都换成对话框。
- Q23b：私教不自动开口。学习者点一下（快捷回复或自己发消息）才调模型。
- Q23c：看板每天一段对话，进对话列表。
- Q23d：去掉 advice 的模型调用和缓存，保留算法候选。
- Q23e：私教开口前，对话框里显示一句按规则生成的问候，以及由候选生成的快捷回复。
- Q23f：结果页沿用这次测试的规划对话。
- Q23g：对话框和对话页一样，支持附件和录音。

## 决定

### 1. 看板：每天一段“今天”对话
- `conversations.purpose` 新增 `daily`。按学习者时区，每天最多一段；**懒创建**：第一次发消息时才建，只是打开看板不建会话、不调模型。
- `GET /conversations/today`：返回今天的 `daily` 会话，没有就返回 `null`。`POST /conversations {purpose: "daily"}`：今天已经有就返回那一段（200），没有才新建（201），所以并发发送也不会建出两段。
- 每轮的 system prompt 带“今天的依据”：复用 `PlanningBrief`（候选、最近一次入学测、没掌握的错题语法点），提示词换成 `prompts/daily.md`，强调“今天做什么”，不重复总结入学测。卡片范围和规划对话相同（`PlanningBrief.scope()`）。
- 其他都和普通对话一样：绑定工具、后台反思（记忆、语法打标、收词）、计入看板的对话轮数和打卡、出现在对话列表（带图标）、可以在对话页继续。
- 没有开场白，也就没有额外的开场调用：私教的第一句话就是对学习者第一条消息的回复。

### 2. 开口前：规则问候 + 快捷回复（不调模型）
- 今天还没有对话时，对话框显示：
  - 一句按规则生成的问候，比如“今天有 23 个词到期，想先做什么？”；
  - 若干快捷回复。第一个固定是“今天学什么？”，其余由候选生成，比如“帮我复习到期的 23 个词”“我想练一下现在完成时”。
- 点快捷回复就等于学习者发了这句话。它作为学习者的消息保存，走正常的一轮对话。文字按界面语言生成，模板放在 i18n 里。
- 快捷回复只决定学习者“说了什么”。私教怎么回、出什么卡片，仍然受 §1 的候选和卡片范围约束，所以模型编不出不存在的动作。
- 今天已经有对话时，对话框直接显示这段对话，最后一条之后照常可以继续输入，不再显示问候。

### 3. 没配模型或调用失败：规则建议兜底
- `GET /advice` 只返回算法候选（kind、证据数字、语法点、链接），**不调模型、不缓存**。响应里加 `model_ready`（chat 路由能不能解析出模型）。
- `model_ready = false` 时，对话框里的快捷回复换成候选的直达链接，旁边提示“去设置”。这就是原来的模板建议，只是作为兜底。
- 发送时失败（厂商错误等）和对话页一样显示错误；快捷回复仍在，可以重试。

### 4. 入学测结果页：规划对话嵌在页面里
- 结果页的建议列表和“和私教聊聊”跳转按钮，换成同一个对话框组件，绑定这次测试的规划对话（ADR 0015 §6，Q23f）。
- 还没开始时，对话框里显示“和私教聊聊这次结果”按钮（带 `plan_start` 的 AI 标记）。点了就在页面里建会话并开场（现有 `plan_opening`），开场白流式出现在对话框里。直接在输入框发消息也行，这时跳过开场。
- 结果页再次打开时，显示这次测试完成之后建的、最近的那段规划对话。

### 5. 对话框组件
- 从 `ChatApp` 抽出 `TutorPanel`：消息列表、卡片、“私教做了什么”、完整输入框（附件、录音，Q23g）。高度固定、内部滚动，右上角有“在对话页继续”。对话页和两处嵌入共用同一套代码。
- 嵌入时不显示会话列表。

### 6. 去掉的东西
- `advice/writer.py` 的模型调用（`describe()` 保留，规划和今天的提示词还在用它）、`AdviceRefresher`、`POST /advice/refresh`、`learning_advice` 表（迁移删除）、`features.yaml` 的 `advice`、`rules.yaml` 里只给缓存用的参数。
- 前端的建议轮询、刷新按钮、“由 AI 生成于…”的说明。

## 公示（ADR 0013、0014）
- `docs/agent-tools.md`：“看板学习建议”一节改写为“今天的对话”。每轮读取依据这一步和规划对话同表；删掉 advice 模型调用那一行。
- `features.yaml`：去掉 `advice`。快捷回复和输入框一样挂 `chat_message`，结果页的开场按钮挂 `plan_start`。

## 取舍
- **不自动开口**（Q23b）：第一眼少了“私教主动跟你说话”的感觉，但打开看板不花 token。规则问候加快捷回复弥补这一点：学习者点一下就进入对话。
- **每天一段**：一段对话只要持续到当天结束，上下文就不会过长，摘要也按天生成。代价是对话列表里每天多一条。之后可以按需要加“隐藏每日对话”的筛选。
- **快捷回复作为学习者消息保存**：历史里能看到学习者点了什么，反思照常处理。这些句子是模板生成的，所以不会被当成语法错误的证据（它们本身没有错误）。
- **去掉 advice 模型调用**：原来的“理由”换成了对话里私教的回复。看板少一次后台调用，也少一张缓存表。
