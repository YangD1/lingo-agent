# 0050 · 学习者要题就出：去掉每天的重测限额，没做完的测验接着做

- **状态**：已采纳（2026-10-16，任务 94；按推荐确认，“接着做还是出新题”用户未选，取两者都支持）
- **日期**：2026-10-16
- **影响**：取代 ADR 0044 §4 的“重测限额”（Q86h）。`rules.yaml` 的 `course.generated_quizzes_per_day` 换成 `course.resume_quiz_hours`（版本 `2026-10-16.2`）；`PracticeWorker.start_quiz` 返回 `QuizStart(set_id, resumed)`；`give_quiz` 新增参数 `fresh`；课程“直接测验”不再返回 409 `quiz_limit`；`tutor_tools.md` 测验一节新增一条；测验卡出题失败的文案改写。无迁移。

## 背景
- 学习者在普通对话里要题，私教回复“今天这节的测试卡不能再生成了，明天可以重试”，然后在回复里自己写了一道题。这种题没经过审题，作答也不进掌握度（ADR 0046 本来就不让这样做）。
- 拦下这次出题的是 ADR 0044 §4 的限额：同一语法点 24 小时内最多生成 2 组过关测验。算进去的两组一组完全没做、一组只做了 1 题。
- 定这个限额是为了防止反复重考、不停花 token。但它不管学习者做没做，没做完的也算一次，学习者等不到题，只能被告知“明天再来”。
- 学习者的要求：“问了就重新生成就好”。

## 决定

### 1. 没做完的测验接着做
- `start_quiz` 先找这位学习者在 `course.resume_quiz_hours`（24）小时内、同一语法点、同一用途（`check` / `quiz`）、还没做完（`generating` / `ready` / `in_progress`）的题组。找到就把它交回去，给新卡片指向它：从没答的题接着做，秒出，不花 token。
- 做完的、失败的、撤回的题组不会被交回（撤回的状态是 `failed`）。超过 24 小时的也不交回：掌握度可能已经变了，重新出更合适。
- 工具结果写明是接着做（“Quiz card shown again … N of M answered so far”），并提示学习者要新题时用 `fresh` 再调。

### 2. 要新题就出新题：`fresh`
- `give_quiz` 新增 `fresh`（默认 false）。学习者说“再出一组”“换一组”、要不一样的题，或者刚做完一组还要时，填 true，跳过续做，直接生成新的一组。
- 生成次数不再限制。花费由学习者自己的模型 key 承担，每次出题的大致 token 数在卡片的 AI 标记和用量页都能看到（ADR 0014）。要限总量，以后按租户预算限，不按语法点。

### 3. 不说“出不了”
- `tutor_tools.md`：不要告诉学习者今天出不了题；卡片出题失败时，学习者还想要就再调一次 `give_quiz`（`fresh`）。
- 失败题组在下一轮上下文里的说明从“自己问一两个问题”改成“学习者还想要就再调一次 `give_quiz`（`fresh` true）”。
- 测验卡失败的文案改成“这次没出成题。跟{name}说一声‘再出一次’，就会重新出。”

### 4. 两张卡共用一组题
- 续做时，新旧两张卡指向同一个题组，答题在任意一张上都算。
- 撤回其中一张（ADR 0049）时，只要还有别的未撤回卡片指向这组题，就不停掉它。

## 没有选的方案
- **只把限额调大**：问题不在数字，而在没做的也算数；调大只是推迟学习者被拦下的时间。
- **只算做完的组**：仍然会有“今天出不了”，而且没做完的组照样每次重新生成、白花 token。
- **每次都出新题**：学习者中途离开再回来，又要等一轮出题，之前做的几题也接不上。

## 后果
- 学习者反复说“再出一组”时，每次都会花一次出题的 token，没有上限。
- `rules.yaml` 版本变化会触发掌握度按证据重算（ADR 0012），没有数据变化，只是一次重放。
