# 0058 · 离开对话回复照常写完，桌宠低头写字，写完举信封提示

- **状态**：已采纳（2026-10-21，任务 115；用户定：做法 A、写字动画、举信封 + 气泡，其余按推荐）
- **日期**：2026-10-21
- **影响**：**补充 ADR 0032 §4a**（桌宠状态加 `writing`）、**ADR 0039 §3**（新增一种气泡）。前端新增 `lib/chat-runs.ts`；`useChatSession` 不再在切会话 / 卸载时取消回复。后端、SSE 协议、ADR 0003 的断开语义都不变。

## 背景
回复由聊天组件里的 `useChatSession` 持有：切换会话、换页面、关掉桌宠小窗都会 abort 请求，后端随即取消图，只留学习者的消息。学习者想离开去做别的、回来看回复，也想在回复写好时被告知。

## 决定

### 1. 回复的流归页面级存储（`lib/chat-runs.ts`）
- 后端接受这一轮（拿到第一个事件，404 / 409 已排除）之后，流交给存储读完；存储记下到目前为止的事件。
- 正在看这个对话的 `useChatSession` 订阅它，事件照旧逐个应用。离开（切会话、卸载）只是取消订阅，不 abort。
- 回到一个还在写的对话：先加载历史（含学习者这条），再接上一条“正在写”的回复，用已到的事件回放，之后的事件继续流入。等历史期间写完了的，结束后重新加载一次历史。
- 只有“停止”按钮会 abort（`stopRun`）。刷新、关闭标签页、跨标签页照旧会断开，后端照旧取消（ADR 0003 不变）。
- 同一对话同一时间只有一个回复（后端会话锁本来就保证）。

### 2. 有没人看的回复在写：桌宠低头写字
- `AvatarState` 加 `writing`：低头、眼睛看下方，像人写字那样把本子竖在胸前：朝向自己、斜靠，学习者看到的是硬纸背面和顶上的线圈；左臂从身体伸出扶住本子侧边，写字的爪子在本子后面，只露出铅笔尾端在上沿左右移动、微微抖动。优先级：listening > speaking > thinking > writing > happy > sleeping > idle（正在看的对话等第一个字时仍是 thinking）。
- 收起成小按钮时（不动画），按钮外一圈转环。
- 多个对话同时在后台写，只显示一种样子；写字状态不算“被冷落”，不会打瞌睡。

### 3. 写完：跳一下，举信封，弹气泡
- 后台的回复写完、且没人在看那个对话时：跳一下（`petHappy`），手里举一个小信封，气泡“回复写好了，回去看看？”；失败时“这条回复没写成，回去重试？”。
- 点“回去看”：是桌宠小窗里的那段对话就重新打开小窗，其他去 `/chat?c=<id>`。已经在 `/chat` 上时，Next 不会重新挂载页面、只换地址：`ChatApp` 跟着 `useSearchParams` 里的 `c` 切过去（它自己用 History API 改地址时，`c` 和当前对话一致，不触发）。
- 和提醒气泡不同：不占每天 3 次提醒的名额；换页面不清掉（它本来就是关于别的页面的）；正在看那个对话、或已经回去看过，就不弹 / 收回。同时有几条，只弹最近一条。
- 小窗开着时气泡照例不显示，关上后出现；收起时显示小红点。

## 取舍
- **只做前端**：比“后端断开后继续跑 + 状态接口 + 续流”小得多，覆盖“站内切走再回来”这个主要场景；刷新仍会丢半截回复，和现在一样。
- **回放而不是重新拉流**：存储里已有全部事件，回来时不用后端支持续传。代价是存储要持有事件到对话被看过或页面关闭，一段回复只有几 KB。
