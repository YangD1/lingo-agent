# 0021 · 练习引擎：题型、选题、出题与 critic、批改、“学会”判定

- **状态**：已采纳（2026-10-02，任务 30；Q5–Q8、Q13 按推荐确认）
- **日期**：2026-10-02
- **影响**：新增 `exercise_sets`、`exercises`、`attempts` 表；`kc_evidence.source` 加 `exercise` / `writing` / `reading`，新增可空列 `format`、`attempt_id`；`kc_mastery` 加 `formats_passed`、`days_passed` 和 FSRS 状态列；`rules.yaml` 加选题和“学会”参数、各题型猜中率；新增模型任务 `exercise_generate`、`exercise_critic`、`exercise_grade`（`features.yaml` 登记 `practice_set`、`practice_grade`）；新增 `backend/evals/`。细节见 `docs/plans/P2-adaptive-reading-writing.md` §3。

## 背景
P1 的学习者模型只有“对话里的错误 → 证据 → BKT”一条输入，入学测是固定的 90 道 choice4。PLAN 第二·五节的闭环（诊断 → 选题 → 生成 → 校验 → 批改 → 证据）还缺后半段。P2 要补上，同时守住两条约束：掌握度只由算法根据证据更新（ADR 0010、0012）；LLM 生成的题必须过 critic 才能给学习者（CLAUDE.md）。

## 决定
1. **题型（Q5）**：第一批六种全做。

   | format | 证据类型 | 判对 |
   |---|---|---|
   | `choice4` | recognition | 代码比对 |
   | `cloze` | recognition | 代码比对（规范化 + 可接受答案列表） |
   | `find_fix` | 找错 recognition；改法 production | 位置代码比对；改法先比可接受列表，不在列表里交给批改模型 |
   | `transform` | production | 批改模型 |
   | `translate` | production | 批改模型 |
   | `rewrite_own` | production | 批改模型 |

   `rewrite_own` 取学习者最近 30 天、来自对话的计入错误的 `kc_evidence.original`。每种题型在 `rules.yaml` 的 `elo.guess_by_format` 登记猜中率（开放题接近 0）。

2. **选题是纯算法**（Q32c–d：候选 KC 是学习者等级往下 2 级到往上 1 级，加上所有有过证据的 KC，没做入学测按 A2 算；`p_mastery` 低于阈值时偏向识别题，高了偏向产出题，并优先还没答对过的题型）（`adaptive/planner.py`，单测）：优先级 = 薄弱度 × 重要度 × 到期 ×（P2d 起）诊断加成；一组约 10 题，约 70% 薄弱 KC、30% 已掌握或到期 KC，同一 KC 不连续、同一题型不连续超过两题；用语法 Elo 能力值和题目 rubric 难度算预计正确率，给生成器 0.80–0.85 的目标难度（85% 规则）。参数放 `rules.yaml`，改了就升版本号（ADR 0012）。
   落地（任务 32.4，`adaptive/exercise/planner.py`）：先按“约两题一个 KC”决定薄弱部分用几个 KC，按优先级轮流分题，每个 KC 一组最多 `max_items_per_kc` 题；已学会的 KC 先取到期的（最早到期在前），再取快到期的，每个一题；任一部分不够时由另一部分补足，候选太少时整组可以不满 10 题。题型按 Q32d 分成“首选 / 次选 × 没答对过 / 答对过”四档，同一档里优先用这组里用得少的题型。排序是“相邻不同”的贪心：每步从允许的题里挑 KC 剩得最多、其次题型剩得最多的；排不下时先放宽题型规则，再放宽 KC 规则。目标难度按 `elo.expected` 反解，让含猜中率的预计正确率等于 `target_p` 的中点。同样的输入和随机种子得到同样的计划。

3. **出题子图**：`plan → generate → critic → (重生成，最多 2 轮) → persist`，用 mock LLM 做图测试。
   - `generate`（`exercise_generate`）一次结构化调用出一组题；输入 KC 说明与常见错误、目标难度、题型、记忆里的兴趣和职业（个性化语境）、`rewrite_own` 的原句。
   - `critic`（`exercise_critic`，可路由到另一个模型）先**不看标准答案**独立作答，再对照检查：答案唯一且正确、确实考这个 KC、难度在目标附近、没有事实或文化错误。不通过的带理由回到 `generate`；两轮仍不过就丢弃，缺的题用入学测题库（按 KC 和难度）补。critic 的判定、理由和独立作答都存在 `exercises.critic`。
   - 学习者可以对单题点“这题有问题”：题目标为 `reported`，这题的作答不计证据。
   - 落地细节（Q33a–g，2026-10-02 确认；任务 33 实现）：
     - **难度（Q33a）**：生成器和 critic 各按入学测的 rubric 评一次级，代码用 `prior_difficulty` 换算；两者相差超过 `practice.critic_max_gap`（0.7）算不通过，存 critic 的评级。生成器拿到的目标是“rubric 偏移量之和”（目标难度减去 KC 等级锚点，限制在 rubric 能达到的范围内），不是 logit。
     - **critic 不看答案**：选择、填空、找错题不给 critic 标准答案，代码比较它自己的答案和标准答案（填空看是否在可接受答案里，找错只比位置），不一致就不通过；开放题给参考答案让它判断。critic 看不到个人语境和 `evidence_id`。
     - **重写（Q33b）**：只重写没通过的位置，带上被拒草稿和理由，一次调用；草稿不合题型格式的直接带原因重写，不送审；审题漏掉的题重写但不算被拒。共 1 + `max_regenerations` 轮；任一次模型调用失败就不再重试。
     - **题库补位（Q33c、Q33g）**：同 KC 没见过 → 同 KC 隔 ≥ `bank_repeat_days`（14）→ 本组其他薄弱 KC（先没见过）→ 学习者等级范围内的其他薄弱 KC（按选题优先级，先没见过）。第四档是 Q33g 加的：一组只覆盖约 5 个 KC，题库每个 KC 约 1 题，只用前三档时没配模型的学习者在模拟中 100% 凑不满。题库题没有讲解，按讲解语言用模板写“考点 + 正确答案”。不足 `min_items`（5）题整组失败。
     - **没配模型（Q33d）**：题库能凑够就整组用题库题，界面注明。
     - **结构化输出用扁平 schema**：各题型字段都是可选字段，代码再组装成 `formats.py` 的模型校验；带标签联合（oneOf / discriminator）在各家厂商的结构化输出里支持不一。
     - **位置不重新编号**：丢掉的位置留空，被拒的题和替换它的题同一个 `position`。
     - **个人语境（Q33f）**：画像里的职业、目标、考试、兴趣 + 最近 8 条事实记忆，只给生成器。

4. **出题时机（Q7）**：开始一组时现生成（约 10–20 秒，等待时显示 hop 猫和进度）；做完一组后，用同一个后台 worker 的方式（参照 `memory/worker.py`）为下一组预生成。预生成登记为 `timing: background`，受 ADR 0025 的每日上限约束，学习者可关。
   落地（Q33e）：每人最多一组没人开始过的预生成组；超过 `practice.prefetch_max_hours`（24）或规则版本变了（`exercise_sets.rules_version`）就标 `failed/expired` 重出；开始练习时优先用正在生成的组（含重复点击）和预生成组。进程重启时还在 `generating` 的组标 `failed/interrupted`。每日上限和学习者开关在任务 40 接上，目前默认开。

5. **题目归属（Q8）**：生成的题按学习者私有（带个人语境），不跨用户、不跨租户共享；入学测 `items.yaml` 是全局兜底题库。

6. **批改（Q6）**：代码能判的直接判；开放题交给 `exercise_grade`（结构化输出）：目标 KC 判对 / 判错（只有两档）、讲解与正误对比、答案里**其他**语法错误（KC id 必须在清单里，严重度规则同对话反思）。目标 KC 的结果按题型的证据类型记一条；其他错误各自记证据。批改模型只判断“这一次答得对不对”，掌握度仍由 BKT 根据证据更新。每次作答写 `attempts` 和 `kc_evidence`（`source=exercise`，`format` 按题型，`attempt_id` 指回作答），然后刷新掌握度；作答后按 Elo 更新学习者的语法能力（题目难度不校准，见下）。
   - 落地细节（Q34a–f，2026-10-02 确认，任务 34）：开放题和参考答案规范化后一致直接判对，不调模型（a）；每题只算第一次作答，再交返回第一次的结果（b）；每次计入的作答按整题对错、题目难度和题型猜中率更新 `skill_estimates` 的 grammar，没有记录时从等级锚点起步（没测过按 `practice.default_level`），生成题不校准难度，题库题不回写全站统计（c：生成题只做一次，校准没有意义；练习里的作答条件和入学测不同，混进全站统计会污染入学测）；批改模型失败时不存作答，请学习者重交（d）；其他错误各记一条证据，严重度按模型给的、计入规则同对话（e）；find_fix 位置错只记一条识别错，位置对再按改法记产出，改法不在列表里交给模型（f）。目标语法点答错的证据固定记 `wrong_choice` / `medium`（批改结果只有对错两档），原文是学习者的答案，改正是模型改好的句子或参考答案。批改调用前结束读事务，写入前锁题目行再确认没答过，所以并发提交也只记一次。举报（`reported`）删掉这题作答产生的证据并重放，作答本身保留；那一步 Elo 不回退（Elo 依赖顺序，无法精确撤销，影响只有一步）。

7. **“学会”与语法点 FSRS**（Q31a–c，2026-10-02 确认）：
   - “学会”= `p_mastery ≥ mastered` **且** ≥ 3 种题型答对 **且** 答对的第一次和最后一次相隔 ≥ 20 小时（“跨 ≥ 2 天”；不按自然日切，画像里没有时区，也避免 23:59 和 00:01 各做一次就算两天）**且** 截至这条证据的前 14 天里，对话和写作中没有这个 KC 的计入错误。阈值都放 `rules.yaml`。
   - 第一次满足条件的那条证据记为 `mastered_at`；之后这个 KC 的每条练习证据按答对 Good / 答错 Again 交给 FSRS（复用 `fsrs` 库和单词的参数），到期后进入选题的“到期”部分。
   - FSRS 状态和上面几项进度**都由 `kc_evidence` 重放得出**，和 `p_mastery` 一样只是 `kc_mastery` 里的缓存：判断只看证据和证据的时间，不看“现在”，所以规则改了可以整体重建，结果和证据始终一致（ADR 0012）。
   - 落地细节（Q32a–b，2026-10-02 确认）：FSRS 按练习组各记一次复习，组里这个 KC 有一题错就是 Again，全对是 Good；学会之后，对话或写作里这个 KC 的计入错误也记一次 Again（用对了不记 Good）。重放要求结果确定，所以语法点的 FSRS 关掉 fuzzing，记忆保持率复用单词的 `vocab.desired_retention`。`p_mastery` 跌到 `bkt.weak` 以下时撤销“学会”：清掉 FSRS 状态，答对过的题型和答对首末间隔从这条证据之后重新累计。
   - 第一次复习评 **Easy**（任务 32.2 实现时定）：新卡评 Good 会进入以分钟为间隔的 Learning 步骤，和“已经跨天、多种题型答对”矛盾；Easy 让卡直接进入复习状态，默认参数下首个间隔约 8 天。完成门槛的那组里如果随后又错，第一次评 Good。
   - 学习者模型页显示这四项条件的进度。

8. **最小评估集（Q13）**：P2a 就建 `backend/evals/`（pytest 驱动，ADR 0005）：critic 能拒掉一组已知坏题（答案不唯一、答案错、考错了 KC）；批改能判对一组已知答案。默认用录制下来的模型输出回放（不调用真实 API，CI 可跑）；加参数可以用真实模型跑。学习者“报告有问题”的题作为以后补充评估集的候选。CI 回归和看板留到 P4。

## 取舍
- 六种题型一起做，比先做三种代码能判的多了批改模型的调用和评估工作；但只有选择和填空的话练习会很死板，`rewrite_own` 正是个性化的核心，所以一次做全。
- 开放题只有对错两档，部分正确的信息靠“其他错误另记证据”保留，不改 BKT 公式；代价是“目标结构用对了但不太自然”这类答案只能判对，讲解里说明。
- 题目私有意味着每组都要花 token；租户共享题库能省，但要去掉个人语境，和“个性化语境”目标冲突。以后如果 token 成为问题，可以把 critic 通过、没有个人语境的题再做共享。
- 现生成第一组要等 10–20 秒；每晚批量预生成能免等，但会给不练习的人也花 token，而且要先有定时任务。后台预生成下一组是折中。
- critic 和生成用同一个模型时会有同样的盲点，所以 `exercise_critic` 是独立的路由，租户可以配不同的模型；评估集用来量化 critic 的效果。
