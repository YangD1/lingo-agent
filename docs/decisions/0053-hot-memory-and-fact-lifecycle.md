# 0053 · 热记忆的预算与会话内固定、事实的“被替代”状态、写入前查重

- **状态**：已采纳（2026-10-17，任务 90 的 D；用户按推荐确认 Q90d–g）
- **日期**：2026-10-17
- **影响**：修订 ADR 0009 §1（事实的上限按 token 算、删除分成学习者删和私教删）、§3（反思的 `update` / `delete` 不再原地改、真删）、§4（事实在一段会话里固定）。`memories` 加 `status`、`superseded_by_id`，`conversations` 加 `sitting_started_at`，`llm_usage` 加 `cached_input_tokens`（迁移）；系统提示词各节重排；记忆页加“已被替代”一节；`docs/agent-tools.md` 反思一行同步。

## 背景
任务 90 的 A–E（ADR 0052）解决了新会话“带什么进来”。剩下的 D 借鉴 [dsh-memoir](https://github.com/Qinling-Melon-Farmers/dsh-memoir)：高价值记忆有 token 上限、每个会话开始时固定以便前缀缓存，记忆不自动删而是标成“被替代”，写入前查近似重复。对照代码：

1. **事实已经有上限，但按字符算**：`context.MAX_FACTS_CHARS` 3000 字符、按更新时间取新的。中文 3000 字接近 3000 token，英文只有约 750 token，两种语言差了四倍。
2. **前缀每轮都变**：系统提示词的顺序是“规则 → 名字 → 语言 → 画像 → 近况 → 事实 → 摘要 → …”。近况（ADR 0052 §1）每做一道题都会变，摘要按学习者这一句检索、每轮都变，所以前缀在画像之后就断了。只固定事实拿不到缓存，必须先把稳定的部分挪到前面。
3. **缓存命中没有记录**：`llm_usage` 只记输入、输出 token，重排和固定有没有效果量不出来。
4. **反思的改和删是原地的**：`update` 覆盖原文，`delete` 真删。模型理解错了一次（把“这周忙”记成“不想学了”再删掉旧的），原来那条就找不回来，学习者也看不到发生过什么。
5. **查重只认完全一样的句子**：`apply_reflection` 去掉大小写和句号后比较。“下个月有面试”和“下周有面试”会变成两条；而且模型只看得到最新 60 条事实（`worker.FACTS_SHOWN`），更早的它没法选择更新。

开发库主账号现在只有 1 条事实，离上限很远，这里的收益主要在以后记忆变多时；所以不加置顶和重要度（Q90e）。

## 决定

### 1. 用量记下缓存命中（Q90g）
- `llm_usage.cached_input_tokens`（可空）：取 LangChain `usage_metadata.input_token_details.cache_read`，OpenAI 兼容接口的 `prompt_tokens_details.cached_tokens` 就映射到这里。厂商不给时留空，不是 0。
- 只记录，用量页暂不展示；用来验证 §2、§3 的效果。

### 2. 系统提示词重排：稳定的在前
- 顺序改成：规则 → 名字 → 语言 → 画像 → **事实** → 近况 → 摘要 → 本会话用途（练习 / 计划 / 课程）→ 卡片 → 工具说明。
- 画像和事实在一段会话里基本不变，放在近况前面，前缀能一直延续到事实末尾；会变的部分全部在后面。
- `learner_context.md` 的说明不变，只是各节的位置换了。

### 3. 事实的预算和会话内固定（Q90d）
- **预算按 token 估**：中文、日文、韩文按 1 字 1 token，其余按 4 字符 1 token，事实合计最多 1200 token，按更新时间从新到旧取，取代 3000 字符。估算只用于截断，不追求和厂商的分词一致。
- **一段会话**：学习者发消息时，如果这个会话上一次更新已经过去 30 分钟以上（或从来没有），把 `conversations.sitting_started_at` 设为现在；和闲置补写摘要（ADR 0052 §2）用同一个 30 分钟。课程会话隔天回来就是新的一段。
- **固定什么**：这一段开始之后由反思**新增**的事实，下一段才进 prompt（它们说的内容就在这段对话里，模型本来看得到）。以下几种下一轮就生效：
  - 学习者在记忆页删除、编辑、新增的（ADR 0009 §4：删掉的下一轮就不能再用）；
  - 被替代的旧条不再出现，替代它的新条马上出现（这是对已有内容的修改，不是新增）；
  - 画像（学习者手改的和反思改的都是）。
- 实时语音每通电话本来就只在开场装一次上下文，不受影响。

### 4. 事实的“被替代”状态
- `memories.status`：`active` / `superseded`；`superseded_by_id`（指向替代它的那条，可空，`ON DELETE SET NULL`）。只对 `fact` 用，摘要（`episode`）一个会话一条、照旧覆盖。
- 反思的 `update(id)`：新写一条 `active`，旧的标 `superseded`、指向新的。反思的 `delete(id)`：只标 `superseded`、不指向谁。都不再真删。
- 学习者的操作：
  - 编辑：在原条上改（这是学习者自己的更正，不留历史）；
  - 删除：真删，连同被它替代过的那串历史一起删；清空：全部真删，包括历史；
  - 恢复：把一条被替代的改回 `active`、清空 `superseded_by_id`，替代它的那条不动，学习者可以再删。
- 被替代的不进 prompt、不给反思看、不占 100 条上限（`reflection.MAX_FACTS`）。每人最多留最近 50 条被替代的，再旧的在写入时真删。
- 接口：`GET /memories` 默认只给有效的，加 `include_superseded=true` 才带历史，每条带 `superseded_by_id`。记忆页每条事实可以展开看它替代了什么；列表底部收起一节“已被替代（N）”，可以恢复或删除。
- 公示：活动 `reflect_memory` 的字段不变（`updated` 仍是记忆 id，现在指新写的那条），`agent-tools.md` 写明“更新 = 新写一条、旧的标被替代，可在记忆页恢复”。

### 5. 写入前查近似重复（Q90f）
- 反思要新增的每一条，先和这个人**所有**有效事实比（包括模型没看到的 60 条以外的）：词集合用 `retrieval.tokens`（中文 2 字组、英文词），算 Jaccard；配了 embedding 时再看余弦相似度，任一达到阈值就算重复。
- 重复时按“替代最像的那条”处理（同 §4 的 `update`），不多调模型：学习者改口（“下个月 → 下周”）、前后矛盾（“喜欢先做题 / 喜欢先听讲”）都是新说法生效，旧的可以在记忆页恢复。
- 阈值在实现时用一组中英例子定，写回本节。

## 没有选的方案
- **只固定、不重排**：近况和摘要排在事实前面且每轮都变，固定事实拿不到任何前缀缓存。
- **整个会话一直固定**：课程会话会隔天回来，固定整个会话就几天看不到新记下的事。
- **置顶 / 模型打重要度**：现在的记忆量远没到上限；模型打分不稳定，学习者置顶要改界面和迁移，等真不够用了再加。
- **重复时再调一次模型选更新还是新增**：每次疑似重复多一次 `reflect` 调用，还要改 `features.yaml`；而“新说法替代旧说法”在改口和矛盾两种情况下都对，错了也能恢复。
- **重复时直接丢掉新的**：学习者改口会被丢掉。
- **学习者删除也只标被替代**：违反“用户能真正删除自己的记忆”（ADR 0009 §1）。

## 后果
- 每次反思写入多一次和全部有效事实的比较（最多 100 条，在进程里算）。
- `memories` 里多出被替代的行，每人最多 50 条。
- 一段会话里新记下的事实要到下一段才进 prompt；同一段里模型靠对话本身知道这些事。
- 缓存的实际收益看 `llm_usage.cached_input_tokens`，冒烟时记录。
