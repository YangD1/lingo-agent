# 0013 · Agent 工具调用规范与活动公示

- **状态**：已采纳（2026-09-29；第 3 条的展示方式、开关、排期由用户确认）
- **日期**：2026-09-29
- **影响**：新增 `docs/agent-tools.md`（agent 用到的所有工具、MCP、后台步骤的公开清单）；CLAUDE.md 架构约束加一条；计划新增“agent 活动公示”任务。

## 背景
P1 的私教还没有 LLM 工具调用：对话是固定流程（`load_context → tutor`），记忆和错误打标在回复后的后台反思里做。P2 起会加 Supervisor、GraphRAG 查询、查词典、新闻检索，也可能接 MCP。用户提出两个要求：开发时要考虑 agent 工具调用本身的特性；agent 循环里用了哪些工具、MCP 要公示，既写在文档里，也在界面上让学习者看到。

## 决定

### 1. 工具调用的开发规范
给 agent 加任何工具（LangGraph tool、MCP 工具、需要模型决定是否调用的函数）时，必须满足：

- **身份从运行时注入，不从模型参数来**：user_id、tenant_id、会话 id 只从 `Runtime.context` 取，工具的参数 schema 里不出现这些字段。需要引用已有数据时，用短 id 映射（和反思里的 `m1`、`u1` 一样），模型编不出别人的数据。
- **可能并行调用**：模型一次可能返回多个 tool call，执行要能并发，结果按 `tool_call_id` 对应回去；工具之间不能依赖调用顺序。
- **失败返回给模型，不中断整轮**：工具出错时返回一个标明失败的工具结果，让模型调整或向学习者说明；给学习者和日志的是安全摘要，不带厂商原文和堆栈（与 ADR 0008 一致）。
- **循环有上限**：每轮对话的工具调用轮数设上限（LangGraph `recursion_limit` + 每轮最多 N 次工具调用），到上限就让模型直接作答，防止死循环和费用失控。
- **工具结果是不可信数据**：网页、新闻、MCP 返回的内容可能带提示注入，只作为数据放进消息，不当作指令；不能因为工具结果去调用有副作用的工具而不经过规则校验。
- **有副作用的工具要幂等、可撤销**：写记忆、加生词这类操作要能重复执行不出错，学习者能在页面上撤销；影响大的（删除数据、对外发送）要学习者确认。
- **按需绑定**：工具的描述和 schema 会占 prompt，按场景只绑定需要的工具；MCP 默认关闭，按租户开启，只开放白名单里的工具，设超时。stdio 形式的 MCP 服务不在 prod 运行（内存限制）。
- **可观测**：每次工具调用记录名称、状态、耗时（OTel span 已覆盖 LangGraph 节点；业务侧记到活动记录，见第 3 条）。

### 2. 公开清单 `docs/agent-tools.md`
agent 用到的每个工具、MCP 服务、后台步骤都登记在这份清单里：名称、何时触发、读哪些数据、写哪些数据、调用哪个模型任务、学习者在哪里能看到和撤销。**新增或修改工具时必须同步更新清单**，和 PLAN 同等对待。

### 3. 界面公示
学习者能在对话里看到私教这一轮做了什么：
- 每条私教回复下方有一个可展开的“私教做了什么”：本轮读取了哪些记忆、调用了哪些工具，以及回复后后台记下的内容（新增或修改的记忆、标记的语法错误和对应的语法点）。
- 数据来源是一张活动记录表（每步一行：类型、名称、状态、耗时、面向学习者的摘要），对话中的步骤通过 SSE 实时推送，后台步骤完成后写入，前端在回复完成后再取一次。
- 摘要只含白名单字段（数量、语法点名称、记忆内容），不含 prompt、模型原始输出和错误原文。
- 默认显示为收起的一行（如“读取 3 条记忆 · 记下 1 条 · 标记 2 个语法错误”），点开看明细，明细里链到记忆页和学习者模型页。
- 学习者可以在设置里隐藏；隐藏只影响显示，记录照常保存，记忆页和学习者模型页仍然能看到全部内容。
- 排期：P1 任务 8b，紧接在任务 8（错误打标）之后。

### 4. 实现（任务 8b，2026-09-29，细节由用户确认）
- 表 `agent_activities`：(会话, 轮, 步骤名, call_id) 唯一，写入用 upsert，反思重试不会写出两份；**轮 = 学习者消息 id**（发送前就生成，打标证据也按它记）。
- 身份注入：`ChatContext.activity`（`ActivitySink`）在接口层绑定用户、会话、轮次，图和以后的工具只调用 `record(step)`，拿不到这些 id。写活动失败只记日志，不影响回复和反思。
- 可公示的字段由 `app/activity/service.py` 按步骤名登记的 Pydantic schema 限定。**记忆只存 id**（用户选择）：接口按当前内容解析，删掉的显示“已删除”，不留副本。
- 推送：图的流改为 `messages` + `custom`，节点用 `stream_writer` 发出活动，SSE 事件 `activity`；`done` 带 `turn_id`（ADR 0003 §2 已同步）。
- 后台结果：前端在 `done` 后 60 秒内按递增间隔轮询（用户选择，不让 SSE 挂着等反思），接口的 `pending` 表示该会话反思还在排队或运行，为 false 即停。
- 隐藏开关存浏览器 localStorage（用户选择），只影响本浏览器的显示；隐藏时前端也不再请求活动。

## 取舍
- **公示的粒度**：展示到“做了哪类事、结果是什么”，不展示原始 prompt 和模型输出：前者对学习者有意义，后者既冗长又可能泄露系统提示和其他实现细节。
- **后台步骤也要公示**：反思是异步的，回复完成时还没有结果；为了让学习者知道“私教记下了什么”，前端在回复后补取一次，而不是只展示实时步骤。
