# 0015 · 私教工具调用与确认卡

- **状态**：已采纳（2026-09-30；Q21a–Q21d 和 §8 的 5 条新决定都由用户确认，§8 按推荐）
- **日期**：2026-09-30
- **影响**：对话图加工具循环；新表 `tutor_cards`；`conversations` 加 `purpose` 列；SSE 新增 `card` 事件；新增确认 / 拒绝 / 撤销接口；`features.yaml` 新增 task；`docs/agent-tools.md` 的“LLM 工具调用”一节第一次有内容。遵守 ADR 0013 §1 的全部规范。

## 背景
P1 实测反馈：做完入学测后应该有学习建议，并且能直接进入和私教的对话，由私教帮学习者设置词书、语法练习、学习目标。现在的私教不能调用任何工具：图是 `load_context → tutor`，学习者只能自己去各个页面设置。

用户已确认（2026-09-30）：
- Q21a：放在 P1 做。
- Q21b：有副作用的操作，私教只能提议。界面出确认卡，学习者点了才执行，执行后可以撤销。
- Q21c：普通对话都绑定工具，练习会话不绑定。
- Q21d：工具范围是选词书与每天新词数、开语法练习、复习 / 筛词 / 重测的直达卡片、设学习目标与每天时长。

## 决定

### 1. 图：`load_context → tutor ⇄ tools → END`
- `tutor` 的回复里有 `tool_calls` 就进 `tools` 节点，执行完回到 `tutor`；没有就结束。
- **上限**：每轮最多 2 次工具往返（`MAX_TOOL_ROUNDS`），每次最多执行 3 个调用，多出来的调用直接返回“超出上限”的工具结果。到上限后，最后一次 `tutor` 调用不再绑定工具，模型只能直接作答。LangGraph 的 `recursion_limit` 按这个上限设，作为兜底。
- **`tools` 节点自己写，不用 prebuilt `ToolNode`**：要在节点里做四件事，自己写更清楚。
  - 同一次的多个调用并发执行，结果按 `tool_call_id` 对应回去。
  - 每个调用单独设超时。
  - 失败时返回 `status="error"` 的 `ToolMessage`，不让整轮失败。
  - 每个调用写一条 `tool` 类活动（ADR 0013 §3）。
- **身份只从运行时取**：`ChatContext` 新增 `tools: TutorToolDeps`（用户 id、会话 id、轮次 id、sessionmaker），由接口层绑定。工具参数的 schema 里没有任何 id 字段；需要的都从 `Runtime.context` 取。

### 2. 什么时候绑定工具
- 绑定：普通对话，以及学习规划对话（§6）里走 `chat` 路由的轮次。和 `get_structured_llm` 一样，先在链上每个模型上分别 `bind_tools`，再串成 fallback 链。
- 不绑定：
  - 练习会话，包括它的开场（Q21c）；
  - 带图片、走 `vision` 路由的那一轮：识图模型不一定支持工具，这一轮本来也是在讨论图片；
  - 达到往返上限后的最后一次调用。
- **降级**：有些 OpenAI 兼容的服务或模型不支持工具。带工具的调用如果在输出第一个字之前就被厂商以 4xx 拒绝，就去掉工具，同一轮重试一次，并记一条 `skipped` 状态的 `tools` 活动。
  - 没有工具的轮次，系统提示里换成“不能代为操作”的说明，并附上允许使用的站内链接（`/vocab/books`、`/vocab/review`、`/vocab/screen`、`/placement`、`/learner`、`/memory`）。私教只给建议，并用 Markdown 链接指路。
  - 前端只让这些站内相对路径成为可点的链接。

### 3. 工具
工具名、描述和参数都用英文写，参数用 Pydantic 定义；参数取值只能来自公开目录或本轮上下文。

| 工具 | 参数 | 有无副作用 | 结果 |
|---|---|---|---|
| `propose_word_book` | `book_id`（词书目录的枚举）、`daily_new`（0–200，可省略） | 有 → 确认卡 | 返回“已提议，等待学习者确认”和卡片 id |
| `propose_learning_goal` | `goal`（≤200 字）、`target_exam`（和画像同一个枚举，可省略）、`daily_minutes`（1–600，可省略） | 有 → 确认卡 | 同上 |
| `suggest_practice` | `kc_id`（必须在语法目录里；规划对话里还必须在给出的候选里） | 无 → 练习卡 | 卡片上的按钮打开或新建该语法点的练习会话，走现有的 `/chat?practice=` 流程 |
| `suggest_link` | `kind`：`vocab_review` / `vocab_screen` / `placement` / `learner` / `word_books` | 无 → 直达卡 | 卡片显示实时数字（待复习多少、剩余新词多少、距上次测试几天），数字取自 `advice/candidates.py` |

- 工具只做校验和写卡片，**真正修改学习者数据的只有确认接口**。模型编造的词书、语法点等参数，在工具里就被拒绝，作为错误结果返回给模型。
- 同一轮里重复提议同一件事（同类型、参数相同），复用已有的卡片，不新建。

### 4. 卡片的存储与状态机：新表 `tutor_cards`
每张卡片是表里的一行，字段如下：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 卡片属于谁 |
| `conversation_id` | 所在会话 |
| `turn_id` | 学习者那条消息的 id，和活动记录一致 |
| `tool_call_id` | 模型给出的调用 id |
| `kind` | `word_book` / `learning_goal` / `practice` / `link` |
| `params` | JSONB，校验后的参数 |
| `status` | 见下 |
| `before` | JSONB，执行前的旧值，撤销时用 |
| `created_at` / `decided_at` / `undone_at` | 时间 |

- `(conversation_id, tool_call_id)` 唯一，节点重试也不会写出两张卡。
- 状态流转：
  - 有副作用的卡：`proposed → applied | declined`，`applied → undone`；
  - 无副作用的卡：状态固定是 `info`。
- 接口，都只允许卡片的主人调用：
  - `POST /cards/{id}/apply`：在一个事务里重新校验参数，把当前值存进 `before`，执行，状态改为 `applied`。重复调用返回当前状态，不会执行第二次（幂等）。
  - `POST /cards/{id}/decline`：拒绝提议。
  - `POST /cards/{id}/undo`：把 `before` 写回，状态改为 `undone`。只有在相关设置没被改动过（当前值还等于这张卡写入的值）时才能撤销，否则返回 409，界面提示“设置已被改过，请到对应页面调整”。
- **撤销还原的范围**：
  - 词书：还原原来的书、每天新词数和筛词进度（`screen_offset`）；如果原来没选过词书，就删掉这条计划。
  - 学习目标：还原 `goal`、`target_exam`、`daily_minutes` 和 `manual_fields`。
  - 确认后写入的画像字段都记进 `manual_fields`：学习者自己点了确认，就等于手动设置，之后的反思不会再覆盖它。
- 没处理的提议一直保留，不设过期时间。新提议不会让旧提议失效，每张卡独立确认。
- 私教下一轮怎么知道结果：`load_context` 把本会话最近的卡片及其状态放进当轮上下文（例如“c1 换成 CET-4 词书：已确认”）。这部分不进 checkpoint，和学习者上下文一样。

### 5. 流式输出与历史
- **SSE**：新增 `card` 事件，工具节点写完卡片就推送。token 流不变：同一轮里两次 `tutor` 调用的文字，前端接在同一个气泡里；`done` 的 `message_id` 取这一轮最后一条 AI 消息的 id。
- **checkpoint 保留完整的工具消息**：带 `tool_calls` 的 AI 消息和 `ToolMessage` 都存，下一轮模型才能看到完整上下文。工具结果里只有卡片 id 和简短状态，不含个人数据以外的东西。
- **历史接口** `to_chat_messages`：把同一轮的 AI 消息合并成一条私教消息，去掉 `ToolMessage`；卡片从 `tutor_cards` 按 `turn_id` 取，显示的是当前状态。
- **反思**：只看学习者消息和合并后的私教文字，工具调用和工具结果都不算学习者的话，也不打标。

### 6. 学习规划对话（任务 21.3）

> **2026-10-01 修订（ADR 0016 §4）**：结果页不再跳转到对话页，规划对话直接嵌在结果页里；开场、依据和卡片范围不变。
- `conversations` 加 `purpose` 列（可空；`planning` 表示规划对话），和练习会话用的 `focus_kc_id` 并列。
- 规划对话由入学测结果页的“和私教聊聊怎么学”创建，私教先开口，开场复用练习开场的机制。
- 注入的上下文：入学测结果，以及算法给出的建议候选（`advice/candidates.py`）。`suggest_practice` 的 `kc_id`、`suggest_link` 的 `kind` 必须在候选范围内，超出的调用在工具里被拒绝。
- 实现补充（任务 21.3）：
  - 刚做完入学测的学习者通常还没有对话错误，语法候选为空。所以“该次入学测答错、且还没掌握的语法点”（最多 5 个）也算在范围内；`/learner` 链接始终可用。
  - 读不到候选时范围为空，只能出换词书 / 设目标的提议卡片。
  - 还没有任何消息（连开场白也没有）的规划对话，再按按钮时直接复用；有了开场白就新建，因为旧开场白说的可能是旧的测试结果。
  - 入学测完成后第一次读取建议时立即重新生成，不受 10 分钟间隔限制（`advice/service.py` `needs_refresh`）。

### 7. 用量与公示
- **用量记账**：带工具结果的后续 `tutor` 调用，通过 metadata 的 `usage_task=chat_tools` 单独记账，不算作 `chat`。这样看板的“对话轮数”（按成功的 `chat` / `vision` 调用计数）口径不变。规划对话的开场记为 `plan_opening`。
  - 两个新 task 都登记进 `features.yaml`（ADR 0014）：`chat_message` 加一条 `chat_tools`（立即，只在私教调用了工具时发生）；新增功能 `plan_start`，挂在结果页的按钮上。
- **公示**：
  - 每个工具调用写一条 `tool` 活动，摘要白名单是卡片 id、卡片类型、成功或失败。
  - 学习者在卡片上的确认 / 撤销是学习者自己的操作，不算 agent 活动；卡片自身会显示状态。
  - `docs/agent-tools.md` 的“LLM 工具调用”一节登记这四个工具。

### 8. 设计中新增的决定（2026-09-30 用户按推荐确认）
1. 带图片的那一轮不绑定工具（§2）。
2. 不支持工具时去掉工具、同一轮自动重试一次，降级为只给建议和站内链接（§2）。
3. 没处理的提议不过期，每张卡独立确认；只有相关设置没被改过才能撤销，否则提示去页面调整（§4）。
4. 确认后写入的画像字段记进 `manual_fields`，反思不再覆盖（§4）。
5. 工具后续调用单独记为 `chat_tools`，看板的对话轮数口径不变（§7）。

## 取舍
- **只提议、不直接执行**：多一次点击，换来学习者对自己数据的控制权。模型误解意图的代价只是一张被拒绝的卡片。
- **卡片单独建表，而不是从 `ToolMessage` 里解析**：卡片状态会在对话之外变化（确认、撤销），存在 checkpoint 里就改不了；表里的一行是唯一的事实来源，历史和实时推送都读它。
- **不做通用的“撤销任意操作”**：只针对这两类设置保存旧值。以后加有副作用的工具，要自己定义 `before` 的内容和撤销的前提条件。
- **工具每轮都绑定，要占 prompt**：四个工具的 schema 约几百 token，每轮都要付出。只绑定在普通对话和规划对话，练习会话不绑定，控制这部分开销。
