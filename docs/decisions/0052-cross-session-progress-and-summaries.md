# 0052 · 跨会话的学习近况、摘要补写与摘要挑选

- **状态**：已采纳（2026-10-17，任务 90；用户按推荐确认顺序 A → B → C → E → D 和 Q90a–c）
- **日期**：2026-10-17
- **影响**：修订 ADR 0009 §1（摘要什么时候写）、§2（没配 embedding 时怎么挑摘要）、§3（摘要的输入和语言）、§4（读取时多一节“现在学到哪”）。`user_profiles` 加 `ui_locale`（迁移）；新增 `memory/progress.py`（近况）、`memory/retrieval.py`（BM25 与去重）；`ReflectionWorker` 加闲置扫描（`sweep_idle`）；活动 `load_context` 加 `progress` 字段；提示词 `learner_context.md`、`reflect_summary.md`、`reflect.md` 修改。

## 背景
任务 90 查了开发库里一个真实使用的账号（13 个会话、约 21 轮、1 条事实、8 条摘要、没配 embedding），新会话开头带进去的东西有这些问题：

1. 没配 embedding 时按时间取最近 3 条摘要。最近三次会话都是“出题给我”，三条摘要几乎一样，更早的词书、must / have to、读新闻都被挤掉。
2. 摘要要满 6 轮或者开新会话时才写。学习者反复回到同一个课程会话时，摘要停在几天前；最后一个会话一直没有摘要。
3. 写摘要的模型只看到聊天文字，看不到卡片和测验结果，8 条里 6 条以“尚未作答 / 待跟进”结尾。做完了它也不知道。
4. 没有类型的会话只带画像、事实和摘要。每日 / 计划会话有 7 天统计（ADR 0041 §3），课程会话有当前课（ADR 0044 §5），但“学到哪了”在普通会话里只能靠摘要。
5. 摘要语言前后不一致。原因是语言取自那一轮请求的界面语言 cookie，进程重启后补做（`worker.recover`）时没有 cookie，就按默认英文写。还有一条摘要写了“这是第一次对话”，写摘要的模型看不到别的会话，这句是编的。

问题 1、3、4 的共同点是：学习进度本来就在数据库里（课程、测验、词书、阅读），却要靠模型写的摘要转述。

## 决定

### 1. 每个会话都带一节“现在学到哪”，由代码数出来
- `memory/progress.py` 读取，不调模型：
  - 课程：当前课（`course.load` 的 `current`）的编号和名字，已过几课 / 共几课；没做过入学测也照样列。
  - 最近 3 组测验（`exercise_sets.origin = 'quiz'`，按创建时间倒序，不含撤回卡对应的）：语法点、过关测验还是理解检查、共几题、答了几题、对了几题（`cards.quiz.quiz_states`，讲过答案的按答错算，同 ADR 0051 §4），没做完的写明。
  - 词书：当前词书名、在学 / 标熟 / 总数（复用看板的统计）。
  - 阅读：最近读完或在读的 1–2 篇文章标题。标题来自外部 RSS，按数据放进 prompt（和工作区文档一样标明是资料）。
  - 最近 7 天学了几天、上次学习是哪天（`chat.recent`）。每日 / 计划会话的简报里已经有这部分，这两种会话不重复写。
- 渲染成 `render_learner_context` 里的一节，常见约 500 字符，最长（语法点名字最长、标题截到 80 字）不到 900 字符；测验行只写语法点 id 不写名字，省长度；放在所有会话里，包括实时语音的开场上下文（Q90a）。
- 读取失败只记日志，这一节不出现，本轮照常回复（和读记忆失败一样，ADR 0009 落地记录）。
- 和记忆一样只进本次 prompt，不进 checkpoint。
- 公示：活动 `load_context` 加 `progress`（布尔，带了这一节），回复下“私教做了什么”写“看了学习近况”。

### 2. 摘要补写：闲置了就写，不只是开新会话
- `ReflectionWorker` 在进程里每 10 分钟扫一次（`sweep_idle`，启动时和重启补做一起开）：最近 2 天内有更新、闲置满 30 分钟、还有没总结进去的对话（没有摘要，或摘要早于会话最后更新）的会话，交给 `ReflectionWorker.schedule(finish=True)`（Q90b）。worker 发现没有新的学习者消息就直接返回，不调模型。
- `finish_previous`（开新会话时补写上一个）保留，它让摘要更早写好。
- 不放进调度器（APScheduler，ADR 0025）：调度器的任务拿不到进程内的反思 worker，而且每 10 分钟一次会在后台任务页和 `scheduler_runs` 里刷出很多记录；重启补做（`recover`）本来就在 worker 里。
- 不加设置开关：摘要属于记忆，部署方仍可以用 `MEMORY_REFLECTION_ENABLED=false` 关掉整个反思。

### 3. 摘要的输入和写法
- **语言**：`user_profiles.ui_locale` 存最后一次聊天请求的界面语言（Q90c，迁移）。worker 拿不到请求 cookie 时（重启恢复、闲置补写）用它；都没有才用英文。
- **卡片结果**：写摘要时，把这段会话最近 10 张卡和测验进度（`cards.service.render_context`，私教每轮看到的同一份，但 `questions=False` 不列题面）一起交给模型。
- **提示词**：写清练了什么、测验结果、还没做完的事；不写它判断不了的跨会话的话（“第一次对话”“又一次”），因为它只看得到这一段会话。

### 4. 挑摘要：BM25 兜底，加去重
- `memory/retrieval.py` 是纯函数：
  - 分词：中文按 2 字组，英文按词（小写），数字算词。
  - 打分：BM25（k1 = 1.2、b = 0.75），会话标题里的词权重加倍；越新的摘要加一点分（按天衰减）。
  - 去重：和已选的摘要在词集合上的重合度（Jaccard）≥ 0.6 的跳过。
- 没配 embedding 时，用学习者这一句和摘要做 BM25，取最高的；这一句太短、和谁都不沾边时（总分为 0）按时间补。配了 embedding 时，向量结果也过一遍去重。空位都按时间、同样去重地补满。
- 每人的摘要最多几百条，每次都在进程里算，不建倒排索引、不加表。

### 5. 抽取提示词：记水平和偏好信号
- `reflect.md` 要求记下学习者表达的水平信号（“这本词书很多词都认识”）和学习方式偏好（“喜欢先做题再听讲”），给正例和反例；一次性的请求（“出题给我”）不算事实。
- 评估集 `evals/` 的记忆反思用例加 2–3 条回放用例，按 ADR 0033 更新基线。
- 实际做法（任务 90.8）：只在原有事实清单和一次性请求清单里各补例子，**不单独加一节“水平信号”**：单独成节后 qwen-plus 会把学习者的语法错误记成“Struggles with irregular verbs”这类事实（错误归证据，ADR 0009 / 0010）。
- 事实语言：`reflection_input` 在目标语言不是英文时，第一行写明“翻译例子、不要照抄”。之前中文账号的事实一直照抄提示词里的英文例句；写在系统提示词里则会让模型把档案字段重记成事实。写摘要的提示词同样要求“学习者 / 私教”用目标语言。

## 没有选的方案
- **让模型写一份“进度摘要”**：进度已经在数据库里，模型转述会写错、会过时，也多一次调用；违反“算法负责记账”。
- **多注入几条摘要**（3 条改成 6 条）：三条一样的会变成六条一样的，prompt 更长，问题不变。
- **每轮都重写摘要**：每轮多一次模型调用，而闲置补写已经能让摘要跟上。
- **语言只存在 worker 内存里**：不用迁移，但重启后就丢，正好是现在出问题的那条路径。
- **用 Postgres 全文检索代替 BM25**：内置分词器不切中文，要装扩展（zhparser 等），低配服务器上不划算；每人几百条在进程里算足够快。

## 后果
- 每轮 system prompt 多约 500 字符（最长不到 900）；每轮多几次数据库查询（课程计算本来在课程会话里就有）。
- 闲置补写会多出一些后台 `reflect` 调用，但每个会话只多一次（停下来以后），原来这些对话根本没有摘要。
- 摘要的输入多了卡片状态（最多 10 行、约 200 token，不列题面）。`features.yaml` 里 `reflect` 的估计（13,000 输入）主要是每次反思都带的语法目录，摘要调用又只占一小部分，所以没改。
- dsh-memoir 的热记忆上限、会话内固定、记忆生命周期（任务 90 的 D）不在本 ADR，做的时候另写。
