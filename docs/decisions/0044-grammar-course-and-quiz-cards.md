# 0044 · 语法课程与对话内测验卡片

- **状态**：已采纳（2026-10-15，任务 86；Q86a–h 全部按推荐确认）
- **日期**：2026-10-15
- **影响**：
  - 新增页面 `/course` 和接口 `GET /course`、`POST /course/lessons/{kc_id}`（开课）、`POST /course/lessons/{kc_id}/test-out`（直接测验）。
  - `conversations.purpose` 新增 `lesson`。
  - 助手卡片新增 `quiz` 一种，助手新增工具 `give_quiz`，`suggest_link` 新增 `course`。
  - 练习题型新增 `concept_choice`、`explain`。
  - `exercise_sets.origin` 新增 `quiz`，并新增可空列 `quiz_purpose`（`check` / `quiz`）。
  - `rules.yaml` 新增 `course` 一节。
  - 新增用量功能 `quiz_card`、`lesson_start`。
  - 以上改动需要一次迁移。

## 背景
- 练习引擎（ADR 0021）已经能做出题 → critic → 批改 → 写证据 → BKT / Elo / FSRS 这一整条链，但题只能在 `/practice` 单独做；在对话里，助手只能给一张"做一组题"的链接卡片（`suggest_practice`）。
- 学习者希望像通用助手那样**题目直接出现在对话里**：点选、提交、当场判对错、看解析，最后看到"测验结果 · 通过"；并且希望**成体系地学**：第一课、第二课……每个阶段该掌握什么是清楚的，过关了才往下走。
- 现有的"对话练"（`focus_kc_id`，grammar_coach）不带工具，没法在对话里出题卡片。

## 决定

### 1. 范围（Q86a）
- 第一版课程**只有语法**：119 个语法点（`grammar.yaml`），已有前置依赖、掌握度、"学会"判定和 FSRS。
- 词汇（背单词）和阅读（分级新闻）以后可以作为"单元"挂进课程，不在本次范围。

### 2. 课程编排（Q86b，纯算法，`adaptive/course.py`）
- **一课一个语法点**，课程 id 就是 KC id。
- 课序：按 CEFR 等级分段（A1 → C2）；同一等级内按前置依赖做拓扑排序，没有依赖关系的保持 `grammar.yaml` 里的顺序（稳定、可复现）；同等级前置找不到时忽略这条边。
- **课程状态读时现算，不另外存表**：

  | 状态 | 条件 |
  |---|---|
  | `passed` 已过关 | 已"学会"（`mastered_at` 不为空）；或最近一次过关测验答对 ≥ `course.pass_score`（0.8）且当前 `p_mastery` ≥ `course.pass_p`（0.8）；或语法点等级低于学习者等级且 `p_mastery` ≥ `course.pass_p`（入学测已经说明会了，不逼着从 A1 学起） |
  | `review` 待复习 | 已过关，但 FSRS 到期（`due` ≤ 现在），或 `p_mastery` 掉到 `bkt.weak` 以下 |
  | `learning` 学习中 | 没过关，有这一课的对话或测验记录（即使前置还没过，比如直接测验过） |
  | `available` 可以学 | 没过关，前置语法点都已过关（或没有前置） |
  | `locked` 未解锁 | 有前置没过关 |

- **解锁**：前置语法点已过关就算满足；低于学习者等级的前置，只要 `p_mastery` ≥ `bkt.weak` 也算满足（入学测说明够用了，不让 A1 的课锁住 A2 学习者的课）。
- **当前一课**：课序里第一个状态为 `learning` 或 `available` 的语法点；低于学习者等级的课只有薄弱（`p_mastery` < `bkt.weak`）时才排在前面，否则从学习者自己的等级开始。没做过入学测时从 A1 第一课开始。看板和课程页的"继续学习"都指向它。
- `locked` 的课不能直接开讲，但可以"我已经会了 → 直接测验"（§5），过了就算过关，后面依赖它的课随之解锁。
- **过关只看算法**（Q86c）：测验得分由代码和批改模型逐题判出，掌握度由 BKT 根据这些证据更新；LLM 不判"过没过关"。
  - 测验得分 = 每题第一次作答答对的题数 / 这组的题数（不含被拒的题）。
  - 按现有 BKT 参数，学习者自己等级的语法点（先验 0.4），5 题里答错第一题、后面 4 题全对，`p_mastery` 约 0.99，所以 0.8 的门槛不会因为错一题就过不去。
  - 只答对 3 题时得分 0.6，不过关。

### 3. 两种新题型（Q86e）
- `concept_choice` 概念单选：问规则本身（"这里为什么用 have done？""哪种说法正确？"）。题干不要求有空位，四个选项、一个正确答案、一段解析，代码判对。
- `explain` 用自己的话解释：一个问题，加上参考要点（1–4 条）。批改模型返回"对 / 部分对 / 需要修正"和一段反馈；学习者可以用中文答。
- **两种题都不写证据**，不影响 BKT、Elo、"学会"、FSRS，`SPECS` 的证据类型为空。原因：能说出规则，不等于会用这个语法。
- 两种题都只在理解检查里出现，不进 `/practice` 的选题。

### 4. 测验卡片（Q86d、Q86f、Q86g，工具 `give_quiz`）
- 参数：`kc_id`，以及 `purpose`：
  - `check`：理解检查，2 题，`concept_choice` + `explain`；
  - `quiz`：过关测验，5 题。
- 题型由代码决定，助手不能指定。
- **过关测验的组题**（`plan_quiz`，单测）：
  - 3 道识别题：choice4 / cloze / find_fix 各一，按现有的规则排顺序，优先还没答对过的题型；
  - 2 道产出题：transform / translate；学习者在这个语法点上有对话错误时，其中一道换成 rewrite_own。
  - 难度沿用 85% 规则（`target_difficulty`）。
  - 先复用题库里出过、学习者没见过的同类题（`exercises` 表里的私有题目只属于本人，所以复用只发生在入学测题库）。
- **出题异步进行**：工具调用有 15 秒上限，出题要几十秒。
  1. 工具先建一个 `exercise_sets`（`origin = quiz`，`focus_kc_id`、`quiz_purpose`，状态 `generating`）。
  2. 后台照常出题 → critic（被拒最多重写两轮）。
  3. 立刻出卡片（`info`，`params` 带 `set_id`、`kc_id`、`purpose`），工具结果告诉助手"题在准备，学习者会在卡片里作答，别在回复里重复出题或公布答案"。
  4. 卡片显示"出题中"并轮询这组题。
  - 生成失败或被拒的空位：测验题用入学测题库的 choice4 补；理解检查没有题库，就整组只留下过了 critic 的题，一题都没有时卡片显示"这次没出成"，助手下一轮口头提问。
  - 测验至少 3 题才算成组（`course.quiz_min_items`），理解检查至少 1 题。
- **作答复用练习接口**：`GET /practice/sets/{id}`、`POST /practice/exercises/{id}/answer`；不写证据的两种题型在 `answer` 里跳过证据和 Elo。
  - 测验组答完不触发 `/practice` 的"预先出下一组"，诊断照常触发（做完一组的规则不变）。
  - 一组测验在 FSRS 里算一次复习（和练习组相同）。
- **卡片交互**（Q86f）：一张卡片放一组题，每题单独提交、当场显示对错和解析（批改模型的题先显示"批改中"）；全部答完显示汇总"测验结果 · 通过 / 未通过"（过关测验）或"理解检查完成"（理解检查）。
- **结果交回助手**（**范围已被 ADR 0051 扩大**：最近一张测验卡列出全部题目，含没答的题和正确答案）：卡片上下文（`describe`）带上这组的得分和答错的题（题干、学习者答案、正确答案）。这些作为数据进下一轮，不进 checkpoint。
  - 汇总下有一个按钮"让 {助手} 讲评"，点了以学习者名义发一条固定消息（"我做完了，帮我看看"），走普通对话一轮。
  - 不自动发，学习者不点就不花 token。
- 任何对话里的 tutor 都可以调用 `give_quiz`：普通对话、看板"今天"对话、课程对话。练习会话（grammar_coach）仍然不带工具。
- `CardScope` 照常限制 `kc_id`：课程对话限这一课的语法点和它的前置。
- 幂等：同一 tool call id 只建一组、一张卡片。
- **重测限额**（Q86h；**已被 ADR 0050 取代**：不再限次数，没做完的测验接着做，学习者要新题才重新生成）：同一学习者、同一语法点，过去 24 小时内已经生成过 2 组过关测验（失败的不算）时，第三组起工具返回错误，让助手告诉学习者明天再测，今天先在对话里练。理解检查不限。
  - 原计划第三组起改用入学测题库出题；实现时发现题库每个语法点最多 2 题，凑不够过关测验的最少 3 题，这条退路永远走不通，所以直接拒绝（2026-10-15 修订）。

### 5. 课程对话（`purpose = lesson`）
- 课程页"开始 / 继续这一课"调 `POST /course/lessons/{kc_id}`：同一语法点已有课程对话时复用最近一段，否则新建，`purpose = lesson`、`focus_kc_id = kc_id`。
- 路由到 tutor（带工具），**不走** grammar_coach；`route_for` 先看 `purpose`。
- **每轮的课程资料**（`chat/lesson.py`，放在练习 / 规划那一段系统提示里，用 `<lesson>` 标出，写明是资料不是指令）：
  - 这一课的语法点：名称、说明、常见错误；
  - 前置语法点和它们的状态；
  - 学习者最近 30 天在这个语法点上的对话错误原句（最多 3 条）；
  - 这一课的测验记录：次数、最近一次得分、答错的题；
  - 当前状态，以及过关后的下一课。
- **开场**（`prompts/lesson_opening.md`，不进 checkpoint）：先用一个小问题激活已有知识（提取练习），再用 3–5 句讲核心规则和 1–2 个例句，然后调用 `give_quiz(purpose=check)` 做理解检查。
- **之后各轮**（`prompts/lesson.md`）：
  - 根据理解检查的结果补讲，学习者表示懂了就出过关测验 `give_quiz(purpose=quiz)`；
  - 过关就恭喜并给"下一课"链接卡片（`suggest_link` `course`）；
  - 没过关就针对答错的题补讲，学习者准备好后再测。
  - 助手不能自己宣布"过关"，以卡片里算出的状态为准。
- **"我已经会了"**：课程页的锁定课、课程对话顶栏都有"直接测验"，调 `POST /course/lessons/{kc_id}/test-out`。
  - 不经过对话模型，直接在课程对话里建一组过关测验和一张卡片（turn id `test-out-<时间>`），只花出题的 token。
  - 这张卡片不挂在任何消息下，前端按时间插到消息之间（排在第一条比它晚的消息前）；为此对话历史的每条消息在写入时记 `created_at`（对话图的 `messages` 用 `add_stamped_messages` 合并，存在 `additional_kwargs`，模型客户端不会转发；之前存的消息没有时间，排序时跳过），`GET /conversations/{id}/messages` 返回它。对话里已有卡片时不再自动开场，免得直接测验后助手又开口讲课。
- 课程对话顶栏（`LessonBar`）：第几课、语法点名称、状态、"直接测验"；过关后显示"下一课"。过关测验做完、每轮对话结束时重新读取这一课的状态。

### 6. 课程页 `/course`
- 按等级分段的阶段地图，默认展开学习者当前等级（没做入学测按 A2）；每课一行，显示序号、名称、状态和掌握度条。
- 顶部是"继续学习：第 N 课 …"。
- 应用侧栏加"课程"。
- 看板"今天的计划"旁加一个课程入口卡片（当前一课 + 进度 x / y）。
- 桌宠快捷指令（"上课 / 课程 / course"）跳转 `/course`，助手可用 `suggest_link` `course`。

## 取舍
- **状态现算 vs 存一张课程进度表**：现算和掌握度永远一致，删除证据后状态自动回退，不会出现两份账对不上；代价是每次打开课程页都要读 119 个语法点的掌握度和测验组，量很小。
- **一课一个语法点**：进度直接对应掌握度。代价是 A1–C2 一共 119 课，有些课很短；课程页按等级分段并默认只展开当前等级，缓解"太长"的观感。
- **前置依赖锁课**：保证体系、不跳着学；"直接测验"给会的人一条快路，不至于被锁死。
- **概念题不计掌握度**：会说规则不等于会用，计进去会让掌握度虚高；它的作用是让助手知道讲解有没有讲清楚。
- **讲评要学习者点**：自动讲评体验更顺，但会在学习者没有要求时花 token；按钮挂 `AiBadge`，学习者自己决定。
- **出题异步**：卡片会有几十秒的"出题中"；同步等会撞上 15 秒的工具超时，也会卡住整段回复。
