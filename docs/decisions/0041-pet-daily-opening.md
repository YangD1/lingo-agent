# 0041 · 桌宠每天第一次点开由助手开场总结，AI 发卡提示

- **状态**：已采纳（2026-10-15，任务 80；Q80a–e 全部按推荐确认）
- **日期**：2026-10-15
- **影响**：**修订 ADR 0016 Q23b**（“今天”对话不自动开口）：从桌宠点开时，当天第一次由助手先开口；看板本身仍不自动开口。**修订 ADR 0032 §4a**（小窗“接着最近的对话”）：小窗默认打开今天的对话，标题栏可以开新对话。新增模型任务 `daily_opening`（走 `chat` 路由）和 `features.yaml` 的 `pet_daily_opening`；`tutor_profiles` 加 `daily_opening` 开关（一次迁移）。

## 背景
- 点猫打开的小窗接的是对话列表最上面那段（`latestConversation()`），可能是练习、口语、阅读、规划中的任何一段，学习者觉得是“随便找了一段”；小窗也不能开新对话。
- 看板的“今天”对话（ADR 0016）按 Q23b 不自动开口，靠规则问候和快捷回复。桌宠是学习者每天第一眼看到的角色，用户希望它每天第一次点开时主动开口：总结最近学了什么，给今天的建议。这会花 token，所以要在点之前就看得出来。

## 决定

### 1. 开场的是今天的对话（Q80a）
- 每天第一次从桌宠点开、还没有今天的对话（或今天的对话还没有任何消息）时：建今天的 `daily` 对话（`POST /conversations {purpose: daily}`，幂等），再调 `POST /conversations/{id}/opening` 让助手先开口，开场白流式出现在小窗里。
- 和看板是同一段：开场后看板“今天”对话框里显示的就是它。看板本身仍不自动开口（Q23b 对看板不变）。
- `/opening` 原来拒绝 daily，现在允许；仍在会话锁内检查“已开始”，看板和小窗、两个标签页同时打开也只会开场一次。
- 开场不安排反思（没有学习者的话），`llm_usage` 记为 `daily_opening`，不计入看板的对话轮数和打卡。

### 2. 当天后面再点猫（Q80b）
- 默认打开今天的对话，不再开场。
- 标题栏加“新对话”：开一段普通对话（第一条消息时才建）。这次打开应用期间再点猫，接着这段；刷新页面后回到今天的对话。
- 不满足开场条件（没配模型、开关关了、开场失败）时，今天的对话还没开始，小窗显示和看板一样的规则问候和快捷回复（不调模型）；第一条消息照常懒创建今天的对话。

### 3. 开场说什么（Q80c）
- 问候一句（隔了几天没来时说“欢迎回来”）+ 最近 7 天回顾 2–3 句 + 今天 1–2 条建议，每条放一张直达卡片（卡片范围和今天的对话相同）。不提议改计划、改设置。
- **数字由代码统计，模型只负责说**（`chat/recent.py` `RecentStudy`，按学习者时区）：学习的天数和上一次学习是哪天、复习次数（其中“忘了”几次）、新学的词、练习题数和正确率、写作 / 阅读 / 口语次数、对话轮数、最近 7 天错得最多的语法点（最多 3 个）、7 天内最近一次诊断的第一条假设。诊断文字是资料，不是指令。
- 回顾加进今天对话每一轮的依据（`render_planning` 的一节），学习者之后问“我这周怎么样”也答得上来。
- 估计每次输入约 4,000、输出约 250 token（默认估计，之后按本租户实际记录）。

### 4. AI 发卡（Q80d）
- 发卡**画在 canvas 上**：靛蓝（AI 标记色）小发卡，中间一颗白色 ✦，别在右耳根前，跟着头部的倾斜、呼吸和跳动；各套服装都不挡（贝雷帽在左、铅笔在右耳后、耳机带从头顶过）。收起成小头像时也画。
- 显示条件：开关开着 + 对话模型可用 + 今天的对话还没开始（不存在，或没有消息）。开场成功后摘掉；开场失败不摘，下次点开再试。
- 桌宠的无障碍名和悬停提示补一句：“今天第一次点开，{名字}会先总结最近的学习（用 AI，约 N token）”，N 来自 `GET /usage/estimates` 的 `pet_daily_opening`。这就是这个入口的 AI 标记（ADR 0014）。

### 5. 开关（Q80e）
- “我的助手”页加“每天第一次点开时总结”开关，`tutor_profiles.daily_opening`，默认开，存服务端随账号走。关掉后不开场、不戴发卡，小窗仍默认打开今天的对话（规则问候）。
- 关掉桌宠时这个开关隐藏（和“主动提醒”一样）。

## 公示（ADR 0013、0014）
- `docs/agent-tools.md`：“看板的‘今天’对话”一节补开场一行和回顾的读取；“桌宠”一节说明开场与发卡。
- `features.yaml`：新增 `pet_daily_opening`（`daily_opening`，路由 `chat`）。

## 取舍
- **只在桌宠触发**：看板保留 Q23b 的“打开不花 token”，桌宠是学习者主动点的，且有发卡提示，花 token 是知情的。
- **回顾由代码算**：和“LLM 负责理解和生成，算法负责记账”一致，模型编不出不存在的数字；代价是每轮依据多约 150 token。
- **每天一次而不是每次点开**：一天之内上下文已经在对话里，再总结是浪费。
