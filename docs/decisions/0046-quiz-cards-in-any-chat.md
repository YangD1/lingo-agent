# 0046 · 普通对话里也出测验卡片，助手按需主动出理解检查

- **状态**：已采纳（2026-10-16，任务 88；按推荐确认）
- **日期**：2026-10-16
- **影响**：补充 ADR 0044 §4。`give_quiz` 新增参数 `topic`、`asked`，`kc_id` 改为可选；`tutor_profiles` 新增 `quiz_proactive`；`rules.yaml` 的 `course` 一节新增 `proactive_quiz_gap_minutes`；`tutor_tools.md` 的测验说明重写。需要一次迁移。

## 背景
- 学习者在普通对话里说"出点题给我测试吧"，助手直接在回复里写了 4 道题，没有出测验卡片。这些题没经过 critic，作答也不进练习引擎，掌握度不会变化。
- 原因有两个：
  - `give_quiz` 必须填 `kc_id`，参数说明是"按上下文给的 id 填"。普通对话的上下文里，只有"最近常错的语法点"带 id，学习者问的"主语 + 动词"（`g.word_order_svo`）不在里面，模型没有合法的 id 可填；
  - `tutor_tools.md` 把 `give_quiz` 写成"讲完规则后检查"和"一课的过关测验"，没有说学习者要题时必须出卡片。
- 学习者希望：要题时自动出卡片；助手判断需要验证理解时，也可以主动出题。

## 决定

### 1. 按名字找语法点：`topic`
- `give_quiz` 新增 `topic`（语法点的名字或描述，中英文都行），`kc_id` 改为可选，二者至少给一个，给了 `kc_id` 就以它为准。
- 代码按语法点的 id、英文名、中文名和说明打分（`adaptive/kc/catalog.py` `find_kcs`）：
  - 只有一个明确命中时，直接出卡片；
  - 有几个接近的候选时，把最多 5 个候选（id 和名称）作为工具错误返回，助手选一个 `kc_id` 再调用一次（工具轮次上限 2，够用）；
  - 一个都匹配不上时，返回错误，说明可以换个说法，或者口头出题。
- 没有把 119 个语法点的清单放进每轮提示词：每轮要多花约 1.5k token，而且大多数轮次用不到。

### 2. 什么时候出卡片（`tutor_tools.md`）
- 学习者要题、要"测一测""考考我"时，**必须**调用 `give_quiz`，不要在回复里写题。默认出 `quiz`（过关测验，5 题，计入掌握度）；学习者明确只想确认听懂了没有时，出 `check`。
- 跨好几个语法点的混合题和词汇题，卡片做不了，仍然可以口头出（这次不做）。

### 3. 助手主动出题：`asked` 和限频
- `give_quiz` 新增 `asked`：学习者这一轮要了题，或者同意了助手提议的测验时填 `true`；助手自己决定出题时填 `false`。
- 偏好开着时，提示词允许助手主动出理解检查：讲完一个规则想确认讲清楚了没有，或者学习者在同一个语法点上反复出错。闲聊、查词、看文章时不出。
- `asked = false` 时，代码会做以下检查，任何一条不满足就作为工具错误返回，助手改成口头问一句：
  - 只能是 `check`。`quiz` 计入掌握度，必须学习者要求或同意；
  - 偏好 `quiz_proactive` 关着时不允许主动出；
  - 同一段对话里，同一个语法点只主动出一次；
  - 同一段对话里，两次主动出题至少间隔 `course.proactive_quiz_gap_minutes`（10）分钟。
- 卡片的 `params` 记录 `proactive`，用来做上面的检查。
- 用时间而不是轮数限频：卡片记录有时间，轮数要从 checkpoint 里数，不划算。
- 课程对话（ADR 0044 §5）不受这些限制：学习者开课就是来学和测的，开场和每次讲完后的理解检查本来就是课程流程，偏好关着也照常出。
- `asked = true` 的调用不受这些限制，只受 ADR 0044 §4 原有的过关测验限额约束。`asked` 是模型自己填的，填错时最坏的结果是多出一组题，而 `quiz` 仍有每天的限额兜底。

### 4. 偏好：`tutor_profiles.quiz_proactive`
- 默认 `true`。助手设置页有开关"允许助手主动出题"，和"自动打开工作区"放在一起。
- 关掉后，提示词改为"只在学习者要求或同意时出卡片"，代码同时拒绝 `asked = false` 的调用。

## 公示（ADR 0013、0014）
- `docs/agent-tools.md`：`give_quiz` 的参数和被拒原因补上 `topic`、`asked` 和限频。
- 没有新的模型调用：主动出的卡片同样记在 `quiz_card` 下，`features.yaml` 的说明里补一句"助手也可能主动出理解检查（可在设置里关掉）"。卡片和"JOJO做了什么"照常显示。

## 取舍
- **`topic` 匹配 vs 每轮带完整清单**：清单最准，但每轮都要多花 token；按名字匹配，大多数情况一次就能命中，模糊时多一次工具调用。
- **主动出题只出 `check`**：理解检查不计入掌握度，出错了代价小；过关测验会改变学习数据，必须学习者点头。
- **限频放在代码里**：只靠提示词，模型可能每轮都出题；按 ADR 0013，限额由代码保证。
- **`asked` 由模型自报**：用代码判断学习者的意图需要多一次分类调用；自报偶尔会错，但后果有限（见 §3）。
