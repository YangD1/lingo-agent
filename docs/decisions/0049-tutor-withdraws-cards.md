# 0049 · 私教可以撤回自己出的卡片

- **状态**：已采纳（2026-10-16，任务 92；Q92a–c 按推荐确认）
- **日期**：2026-10-16
- **影响**：补充 ADR 0015（卡片）、0044 §4（测验卡片）。新增工具 `withdraw_card`；`tutor_cards` 新增状态 `withdrawn` 和列 `withdrawn_reason`（迁移 `a6d5d0cbe419`）；`PracticeWorker` 新增 `cancel`；各卡片工具的返回文字带上卡片 id；`tutor_tools.md` 新增一条。

## 背景
- 学习者问“现在完成时”，助手调 `give_quiz` 时语法点找偏了，出了一张别的语法点的测验卡，然后在回复里说“先不用答这张”。卡片还在，后台还在出题，学习者看到的是一张让人别管的卡。
- 助手已经知道自己出错了，但没有办法收回：工具只能出卡，不能改卡。

## 决定

### 1. 工具 `withdraw_card(card, reason)`
- `card`：卡片 id，就是出卡那次调用的 tool call id。出卡工具的返回文字里写明 `card <id>`（`Card shown (card call_…)`，工作区和测验的返回前缀 `(card call_…)`），下一轮的卡片清单每行也带 `[card <id>]`，所以同一轮和之后几轮都能撤。
- `reason`：给学习者看的一句话（1–300 字），写在收起的卡片上。
- 身份不进参数：只认本会话的卡片（接口层绑定），别的会话的 id 当作“没有这张卡”。
- 所有类型的卡片都能撤（Q92a）。

### 2. 什么时候拒绝（Q92b）
- 学习者已经在卡片上做了决定（确认、拒绝、撤销过的提议）：拒绝，作为工具错误交回模型。撤回不能替学习者回滚设置，要改设置应当出新的提议。
- 测验卡片的题组已经有作答，或者已经开始 / 做完：拒绝。学习者花了时间，作答已经记了证据。
- 已经撤回的再撤：什么都不改，照常返回成功（幂等）。

### 3. 测验卡片顺带停掉出题
- 题组还在出题或刚出完没人答时，标为 `failed`、`error_code = withdrawn`，提交后调 `PracticeWorker.cancel` 取消正在跑的出题任务，不再花 token。出题任务被取消时只在题组仍是 `generating` 时改成 `interrupted`，所以 `withdrawn` 不会被覆盖。
- 撤回的题组不算进每天的过关测验限额（失败的本来就不算）。

### 4. 学习者看到的（Q92c）
- 卡片收起成一行虚线框：“私教撤回了这张卡：<原因>”，可展开看原内容（按只读显示，按钮不可点；测验卡只显示标题，不再加载题目）。
- “JOJO做了什么”记 `withdraw_card` 一行（`card_id`、`card_kind`），摘要“撤回了 N 张卡片”。
- 下一轮卡片清单里这张卡显示 “you withdrew it”，模型不会再提同一件事当作待确认。

## 没有选的方案
- **让模型直接删卡**：学习者会看到卡片凭空消失，不知道发生了什么，违反“学习者能看到私教做了什么”。
- **只靠提示词让模型少出错**：找偏语法点的情况减少不了到零；出了错能收回才是兜底。
- **撤回已确认的提议时自动撤销设置**：撤销是学习者的操作（卡片上的“撤销”按钮），模型替学习者撤会让设置在不知情时变化。

## 后果
- 每张卡片多一种终态，前端、活动摘要、上下文渲染都要认 `withdrawn`。
- 迁移的降级把 `withdrawn` 改回 `info`。
