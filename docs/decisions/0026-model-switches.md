# 0026 · 模型停用开关

- **状态**：已采纳（2026-10-07，任务 51；Q51a–f 已确认）
- **日期**：2026-10-07
- **影响**：补充 ADR 0007 §3（路由解析：跳过停用的模型；链里有停用的模型时不走第 3 层兜底）。`tenant_model_routes` 新增 `disabled` 列（迁移 `9c4d2e6f1a37`）；`PUT` / `GET /tenant/routes/...` 带 `disabled`；新错误码 `models_disabled`；设置页连接卡片和路由卡片加开关。ADR 0004、0007 的其他内容不变。

## 背景
用户想临时不用某个模型（比如中转站涨价、某个模型最近答得不好、测试 key 快到额度），但不想删掉配置，之后还要再打开。之前只有两种办法：

- 删连接：key 和默认模型都没了，还要重配路由。
- 改路由把那一行删掉：之后想恢复，得记得原来的模型名和顺序。

后端早就有 `provider_connections.enabled`，但设置页没有开关；路由里也没有“留着但不用”的概念。

## 决定

### 1. 两级开关
- **连接开关**（Q51a）：设置页每个连接卡片上的开关，读写 `provider_connections.enabled`。关掉后这个连接的所有模型在**所有**任务里都不调用（加载租户上下文时就跳过它），key 和配置都保留。
- **模型行开关**（Q51b）：设置页 4 条功能链（对话、后台整理、看图、语音转写）每一行一个开关。停用的行留在链里、灰显，调用时跳过。存在 `tenant_model_routes.disabled`：停用的 `连接:模型` 列表，**必须是 `models` 的子集**，否则 422。只有租户自定义的路由才有这一列；在没有自定义过的链上点开关，前端会把当前显示的链连同停用列表一起存成自定义（之后可以“恢复默认”）。
- 其他任务（出题、批改、写作批改、分类等）这次不提供单独编辑，靠连接开关管（Q51d）。

### 2. 路由解析（补充 ADR 0007 §3）
1. 按原来的顺序取链（租户自定义 > YAML 任务路由 > YAML 默认路由）；
2. **跳过 `disabled` 里的行**，其余照常只保留租户已有、已启用、key 能解密的连接，顺序不变；
3. **链里有停用的行**、又剩不下可用模型时：**不走**第 3 层兜底（各连接的默认模型），直接报错，错误码 `models_disabled`（Q51c、Q51e）。前端提示“这个功能的模型都停用了，去设置里打开一个”，聊天页带去设置的链接；
4. 链里没有停用的行、只是用到的连接被关掉或删掉时，**照旧**走第 3 层兜底（Q51f）。

### 3. 其他细节
- 连接改名时，在同一个事务里把 `disabled` 里的 `旧名:模型` 一起改写，否则停用会悄悄失效。
- 连接测试按模型所在的链判断测试用途（对话 / 看图 / 转写）时，停用的行仍算在链里。
- 缓存不用另外处理：连接和路由行的 `updated_at` 参与租户上下文的指纹，指纹是模型实例缓存键的一部分，开关一变就自然失效。

## 取舍
- **停用的行“严格不用”，不退回默认模型**：用户亲手停用说明他明确不想用；如果剩不下模型时又悄悄换成某个连接的默认模型，用的可能正是他刚停用的那个模型（默认模型常常就在链里），也可能是他没想到的贵模型。代价是全部停用时这个功能直接不可用，所以要给清楚的提示和入口。
- **只是关掉连接时照旧兜底**：关连接的意思是“别用这个连接”，不是“这个功能别用别的”；而且被关掉的连接本来就不会被兜底调用，不会违背用户的意思。
- **用 `disabled` 列表而不是把 `models` 改成对象数组**：不改原有的数据格式和 YAML 写法，旧数据迁移只需要加一列默认空列表；代价是要校验子集关系、改名时两处一起改。
- **行开关只覆盖设置页的 4 条链**：其他任务目前没有编辑界面，单独为开关做一套界面不划算；需要时再一起做（Q51d）。
