# 0032 · 学习者自选私教：模型、音色、形象

- **状态**：已采纳（2026-10-12，任务 66；Q66a–k 由用户确认，全部按推荐）
- **日期**：2026-10-12
- **影响**：**补充 ADR 0007 §3**（路由解析：对话链按学习者所选模型调整顺序）、**ADR 0028**（交互朗读按学习者所选音色；单词发音不变）、**ADR 0030**（通话模型和音色可由学习者选）、**ADR 0031 §5**（成员可以在主账号的链里挑，扣额度规则不变）。新增表 `tutor_profiles`，新增 `/tutor` 接口和“我的私教”页面；前端新增 Canvas 形象组件，`LingoCat` 退为品牌和加载动画。

## 背景
- 每个用户注册时得到一个个人租户（ADR 0004），设置页的连接和路由其实就是本人的设置；但设置页面向“配模型的人”，按任务、按链编辑，学习者想换个声音要去改路由参数。
- 成员（ADR 0031）没配某项能力时整节借用主账号的链，**自己不能选**：主账号链里有好几个模型、目录里有 48 个音色，成员只能用排第一的那个。
- 核实（任务 66 拆分时）：
  - 音色存在路由参数 `params.voices`（`{连接:模型: {语言: 音色}}`）；朗读缓存键含音色，换音色只是多一份缓存；单词发音按 `words` 路由的音色预生成并可固定。
  - 通话音色按厂商写死（OpenAI `marin`、StepFun `qingchunshaonv`，Qwen-Omni / Gemini 用厂商默认），没有配置入口。
  - 提示词里没有私教名字；没有任何按人存的模型、音色、名字或形象。
  - 前端服务端朗读走一个共享 `HTMLAudioElement`，浏览器朗读走 `speechSynthesis`，通话把 PCM 分块送进 `AudioBufferSourceNode`；三处都没有音量分析。前端没有动画库，`LingoCat` 是手写 SVG + CSS，现在就是聊天回复的头像。

## 决定

### 1. 选什么、影响哪里（Q66a、Q66c、Q66f）
新增“我的私教”，每人一份（`tutor_profiles`，user_id 唯一），各项都可空，空 = 跟随设置页：

| 项 | 作用范围 | 不影响 |
|---|---|---|
| 名字（默认 Lingo） | 聊天、口语、阅读辅导、通话的系统提示词“你叫 X” | 其他提示词 |
| 形象（猫的装扮）+ 毛色 | 前端显示 | 后端 |
| 对话模型（`连接:模型`） | 解析到 `chat` 路由的任务：聊天（含工具）、口语开场与回合、练习开场、计划开场、阅读辅导 | 出题、批改、critic、写作批改、记忆、反思、诊断、改写、翻译等，仍按设置页路由 |
| 朗读音色（`{语言: 音色}`） | 交互朗读：聊天、口语、阅读、跟读示范（`/speech/tts`） | 单词发音（`words` 路由预生成的音色） |
| 通话模型 + 音色 | 实时通话 | — |

- **只做名字，不做性格 / 风格**：风格会改变私教的回复，评估集（ADR 0005）要按风格分别覆盖，以后单独做。
- 出题、批改等不开放个人选择：这些任务的质量由 critic 和评估集兜底，按人漂移会让评估结果失去意义。

### 2. 只能从本人实际可用的里选（Q66b、Q66j）
- `GET /tutor/options` 按本人当前的解析结果给可选项：对话模型 = 实际服务对话链的那一方（自己的，或借用的主账号的，ADR 0031 §5）这条链里未停用、连接可用的模型；通话同理；音色 = 当前朗读链首个模型的音色目录（`VoiceOption`，ADR 0028 / 任务 64.2b），没有目录的模型允许手填。成员能选主账号链里已有的任何一个，主账号不另设白名单。
- 每个选项标“自己的”或“由 X 提供、扣 X 给的额度”。**不做价格表**：没有可靠的单价数据，宁可不显示也不显示错的；试听挂 `AiBadge`，按朗读字符估。
- 保存时后端再校验一次（选项必须在 options 里，音色在目录里或该模型没有目录），不合法 422。

### 3. 解析（补充 ADR 0007 §3、ADR 0031 §5）
- 先按原规则决定这一节用谁的链（自己的 / 主账号的），**个人选择不改变用谁的链、不改变扣谁的额度**。
- 再把所选模型移到链首，其余保持原顺序做后备；所选模型此刻不可用（连接删了、关了、行被停用、退出了主账号、链换成了另一方的）就**静默跟随设置页**，不报错；“我的私教”页显示“已选的模型现在用不了，正在用 X”。
- 朗读：所选音色只替换链首模型（即所选模型）的那门语言的音色；后备模型仍用路由里的音色。缓存键本来就含音色，不用改。
- 通话：所选音色写进 `RealtimeTarget.voice`；为 OpenAI、Qwen-Omni、StepFun 各补一份通话音色目录，Gemini 先用厂商默认（Q66k）。目录里的音色按文档列，任务 64 的真模型冒烟再核实。
- 模型实例缓存键加上个人选择的版本（`tutor_profiles.updated_at`）。
- 个人选择随租户的 provider 上下文一起加载（`TenantProviderContext.tutor`，只挂在本人的上下文上，主账号借出的那份没有），所以聊天、口语、通话、设置页路由卡片的“实际使用”都按调整后的顺序显示。
- 名字写进提示词前校验为一行可打印文本（≤ 40 字），并说明“仍是 AI 私教”。

### 4. 形象（Q66d、Q66e、Q66i）
- **自绘 Canvas 2D，不加依赖**：主体都是 Lingo 猫，预设 5 套装扮：`cat` 不穿装扮（默认）、`classic` 圆框眼镜 + 耳边的笔 + 领结 + 毛衣背心、`casual` 耳机 + 连帽卫衣、`sporty` 运动头带 + 背心 + 奖牌、`artsy` 贝雷帽 + 围巾 + 罩衫。画风按 `docs/design/tutor-pet/2026-10-13-batch1-cats.png` 参考图：深棕粗描边、坐姿全身、奶油色肚子和口鼻、腮红；毛色色板为图里 8 种（橘 / 金 / 米 / 灰 / 蓝 / 黑 / 白 / 粉，默认橘 `#e98b60`），深色猫换黄眼睛、灰肚子。猫身体和各状态只画一套，装扮作为图层叠加；`color` 是**毛色**（任意 hex，阴影和高光由它推出），装扮用自己的固定配色。（2026-10-13 用户调整：原定“Lingo 猫 + 4 个人物风格”改为全部是猫、换装扮，id 不变，不需迁移。）按 `devicePixelRatio` 绘制，页面不可见时停帧。
- 状态：待机（眨眼、呼吸）、听（录音中）、想（等首个 token）、说（口型）、开心（答对、打卡）。
- 口型按**正在播放的音频音量**：服务端朗读把共享的 `HTMLAudioElement` 接到 `MediaElementAudioSourceNode → AnalyserNode`；通话播放器在 `destination` 前插 `AnalyserNode`；浏览器朗读拿不到音频，用 `boundary` 事件模拟。不做音素级口型（只有 Azure 给 viseme，不通用）。
- 系统“减少动态”（`prefers-reduced-motion`）或学习者关掉动画时只画静态图。
- 放在：聊天回复头像（小）和私教面板（大）、口语练习和通话页顶部（大）。`LingoCat` 保留做品牌和加载动画。

### 5. 存储与入口（Q66g、Q66h）
- 存服务端，跨设备同步；“恢复默认”= 删除这一行。学习者可以随时查看、修改、删除（和记忆一样归本人）。浏览器朗读（不走服务端时）挑的本机声音仍存 localStorage，因为声音列表因设备而异。
- 入口：新页面“我的私教”（侧边导航），设置页放链接；非管理员（成员）也能用。

## 取舍
- **个人选择叠加在路由之上、而不是让学习者编辑路由**：路由面向配模型的人，有链、后备、停用等概念；学习者只需要“选一个”。叠加的代价是解析多一步、缓存键多一项。
- **所选模型不可用时静默跟随，而不是报错**：选择是偏好，不是硬约束；主账号调整链、成员退出都不该让成员的聊天坏掉。代价是用户可能没注意到已经换了模型，所以页面上要提示。
- **单词发音不跟着换音色**：单词发音是后台批量预生成、可固定的，换音色就要重新生成整个词书，费用和时间都高；单词听的是标准发音，和私教是谁关系不大。
- **Canvas 自绘而不是 Rive / Lottie / Live2D / VRM**：不加依赖、不引入素材授权问题，低配服务器和手机都能跑；代价是形象比较简单，要自己维护绘制代码。
- **按音量而不是音素做口型**：所有朗读和通话来源都能用；看起来不如 viseme 精确，但对一个卡通形象足够。
