# 0031 · 组织账号与额度：主账号赞助成员的模型与额度

- **状态**：已采纳（2026-10-12，任务 65；Q65a–k 由用户确认，全部按推荐）
- **日期**：2026-10-12
- **影响**：**补充 ADR 0004**（连接和路由仍按租户，新增“赞助关系”：成员没配的能力用主账号的连接和路由）；provider 层的 `TenantProviderContext` 和路由解析带上主账号；`llm_usage` 加付费方和能力两列；新增邀请、成员关系两张表；ADR 0025 的后台预算、ADR 0030 的通话分钟在成员用主账号模型时还要受分配额度约束；ADR 0028 的朗读缓存在成员用主账号朗读时写进主账号的缓存。

## 背景
- ADR 0004：每个用户注册时得到一个个人租户，自己是 owner；连接（含加密的 key）和路由都按租户存；`tenant_members` 的 admin / member 角色和 org 租户只在表结构里预留，没有邀请或加入流程。
- 需求（2026-10-12 用户提出）：一个账号（主账号）把自己的模型连接共享给别人（成员）用，给每个成员按能力分配额度；成员看不到主账号的 key；成员也可以自己配连接，自己配了的能力就用自己的、不扣主账号额度。
- 核实（任务 65 拆分时）：
  - 所有学习数据（对话、记忆、掌握度、单词、阅读……）都按 `tenant_id` + `user_id` 存在本人的个人租户里；如果让成员“搬进”主账号的租户，要迁移几十张表，退出时还要搬回来。
  - `load_provider_context(session, tenant_id)` 有约 30 处调用，包括只有 `tenant_id` 的后台 worker；个人租户和用户一一对应。
  - `llm_usage` 记了租户、用户、token、音频秒数、字符数，但没有“谁付钱”，也没有记这次调用属于哪一节（llm / tts / asr ……）。
  - 后台预算（ADR 0025）和通话分钟（ADR 0030）都是“先查后记”，额度不精确但够用。
  - 记忆向量带 `embedding_model`（`<连接名>:<模型>`），换了模型会在后台重算。

## 决定

### 1. 成员不搬家：赞助关系（D65、Q65a、Q65b）
- 成员仍在自己的个人租户里，学习数据不动；主账号和成员之间新增一条**成员关系**（`org_memberships`）：主账号租户、成员用户和成员的个人租户、状态（`active` / `left` / `removed`）、每项能力的额度、加入时间。
- **任何个人账号的 owner 都能当主账号**，不另建“组织”租户；P4 不做多管理员（`tenant_members` 的 admin 角色保持预留）。
- 一个人同时只能是**一个**主账号的成员（成员用户上的部分唯一索引：`status = active`），要换先退出；主账号不能邀请自己。
- 主账号删除账号时，成员关系级联删除，成员立即回到只用自己连接的状态。

### 2. 邀请与加入（Q65i）
- 主账号建邀请：随机码（128 位，URL 安全），库里只存 SHA-256；默认 7 天有效、次数上限默认 1 次（可改）、可随时撤销。链接是 `/join?code=…`，也可以手输码。
- 加入分两步：先用码**预览**（主账号显示名、会共享哪些能力、各项额度），本人确认后才**加入**。没登录的先注册或登录，再回到加入页。
- 加入时额度从主账号的**默认模板**复制一份，之后主账号可以单独改某个成员的额度。
- 成员可以随时退出，主账号可以随时移除成员，都立即生效；学习数据一直归本人，不受影响。

### 3. 主账号能看到什么（Q65c）
只看成员的显示名、邮箱、加入时间、每项能力的今日 / 本月用量和上限。**看不到**学习数据、记忆、对话、按任务的用量明细。成员能看到主账号的显示名。

### 4. 能力、单位与额度（Q65d、Q65e）
| 能力 | provider 层的节 | 单位 | 用量来自 |
|---|---|---|---|
| 文本 | `llm`、`embedding` | token（输入 + 输出） | `llm_usage` 的 token |
| 朗读 | `tts` | 字符 | `llm_usage.characters` |
| 语音转写 | `asr` | 分钟 | `llm_usage.audio_seconds` |
| 发音评测 | `pronunciation` | 分钟 | `llm_usage.audio_seconds` |
| 实时通话 | `realtime` | 分钟（接通时长） | `speaking_sessions.call_seconds` |

- 每项有**每日**和**每月**两个上限：空 = 不限，0 = 不给用。日按 UTC 天（和 ADR 0025、0030 一致），月按 UTC 自然月。
- 主账号有一份成员默认模板（`tenants.member_default_quotas`），初始值：文本每日 20 万 / 每月 300 万 token，朗读每日 2 万字符，转写每日 30 分钟，发音评测每日 10 分钟，通话每日 30 分钟（每月都不限）。
- 向量调用现在不记用量，量也很小：不单独计量，但跟着“文本”开关走，文本给 0 时向量也不用主账号的。
- 主账号**自己**的用量不受这些额度限制（Q65j），和现在一样。

### 5. 模型怎么解析（Q65f）
- `load_provider_context(session, tenant_id)` 签名不变：按成员的个人租户查到有效的成员关系，就把主账号的连接、路由、版本号作为 `sponsor` 一起带上，并算好这个成员每项能力今天 / 本月还剩多少。
- 解析某个任务时：**先用成员自己的**连接和路由解析；解析出非空的链，就整条用自己的，不拿主账号的模型当后备（账算得清）；自己解析不出来（没配这项），才用主账号的连接和路由解析。成员自己把这个任务的模型全关了（ADR 0026 的 `disabled`）时尊重本人选择，不退到主账号的。
- 判断按**任务**做，而不是整节一刀切：结果上等于“成员配了能用于这项能力的连接就用自己的”，只是某个任务（比如看图）成员的连接做不了时，还能用主账号的。
- 用主账号的模型时：`ResolvedModel` 标上付费租户；模型缓存的 key 用主账号租户和版本；向量的 `embedding_model` 加前缀 `sponsor:`，和成员自己同名连接的向量分开。
- key 只在服务端解密。成员调连接和路由接口时只看到“由 X 提供”和能力列表，不返回 key、末 4 位和 base_url。

### 6. 记账与额度检查（Q65g、Q65k）
- `llm_usage` 加两列：`billed_tenant_id`（用主账号模型时填主账号租户，NULL = 自己付；不加外键，历史比账号活得久）和 `section`（这次调用属于哪一节）。`speaking_sessions` 加 `billed_tenant_id`，通话分钟按它算。
- 额度在**加载 provider 上下文时**检查一次（先查后记，和 ADR 0025 一样，允许最后一次调用超一点）：某项用尽，这项就当成“主账号没有提供”，路由解析抛 `QuotaExhaustedError`（`NoModelConfiguredError` 的子类，错误码 `quota_exhausted`）。各处表现：
  - 聊天、练习、批改：提示“今天（本月）的额度用完了，可以自己配一个连接继续”；
  - 朗读：退回浏览器朗读（ADR 0018 原有的退路）；
  - 后台任务：跳过，下次再来；
  - 实时通话：不能开始；可通话时长取租户上限（ADR 0030）和分配剩余的较小值。
- 后台任务仍按**成员自己租户**的每日后台预算（ADR 0025）；用的是主账号模型时，同时计入成员的文本额度。

### 7. 朗读缓存（Q65h）
成员用主账号朗读时，音频写进**主账号**的缓存（ADR 0028 §3）：成员之间共享，也能用主账号预生成的单词发音；仍记发起人（Q54c），成员退出或被移除时，删掉主账号缓存里他发起的、没有固定的条目。

### 8. 界面
- 主账号：设置页“成员”一节：邀请（复制链接 / 码、撤销）、成员表（加入时间、每项今日 / 本月用量和上限）、单人额度编辑、默认模板；用量页分“我自己”和各成员（`/tenant/usage` 行带 `member`，只含成员在主账号连接上的调用；成员用自己连接的不给看，同 §3）。
- 成员：设置页显示“正在使用 X 提供的：文本、朗读……”和每项剩余，自己的连接照常可配；退出按钮；`AiBadge` 的说明里写明这次扣的是谁的额度。

## 取舍
- **不搬家 vs 加入主账号的租户**：搬家更符合 `tenant_members` 原来的设想，但要迁移几十张表、退出时还要搬回来，还会让主账号的 owner 天然有权看成员数据；赞助关系只动 provider 层和用量表，学习数据隐私天然成立。代价是 `tenant_members` 的多成员设计继续闲置，以后真做“组织管理员看学习报告”时再另写 ADR。
- **按任务判断“自己配了”**：比“整节一刀切”多一点复杂度，但不会因为成员连接做不了某个任务（比如看图）就让这项能力整个不可用。
- **不拿主账号模型做后备**：成员自己的模型挂了不会自动用主账号的，体验差一点，但账算得清，也不会悄悄扣主账号额度。
- **先查后记**：一次长回复可能超出额度一点；换来不用在每次调用前后加锁，和后台预算一致。

## 落地记录（任务 65，2026-10-12）
- **已做**：数据表与迁移 `e3f39baaa371`（65.2）、邀请 / 加入 / 退出 / 移除接口 `/org/*`（65.3）、provider 解析接入主账号（65.4）、额度检查 `app/org/usage.py`（65.5）、设置页“成员”和“主账号”两节与 `/join` 加入页（65.6、65.7）、E2E `frontend/e2e/org.spec.ts`（65.8：邀请 → 加入 → 用主账号模型聊天 → 主账号看到用量并调低额度 → 聊天和路由卡片提示用尽 → 成员自己配连接后照常聊 → 退出，主账号列为已离开）。Q65a–k 全部按推荐。
- **§2 邀请**：邀请码只回一次，库里存 SHA-256；占用次数用一条带条件的 UPDATE，并发加入不会超次数；未知、过期、撤销、用完一律回 `invite_invalid`，不区分原因。`max_uses` 不设 Python 默认值（否则显式传 None“不限次数”也会变成 1）。
- **§5 解析**：`TenantProviderContext.sponsor` 带主账号上下文、名字和已用尽的节；`resolve_route_with_source` 先解析成员自己的，解析不出才用主账号的，和本节一致。
- **§6 记账**：额度在 `load_provider_context` 里算一次（`exhausted_sections`），先查后记；E2E 里一轮聊天加回复后的反思约 100 token，调低上限后下一条消息即被拒。`/usage/estimates` 每个调用带 `provided_by`，额度用尽时也照样写，`AiBadge` 据此说明扣谁的额度。
- **§8 用量可见范围**：`/tenant/usage` 原来只按 `tenant_id` 查，成员在主账号连接上的调用记在成员自己的租户下，主账号看不到；改为同时取 `billed_tenant_id = 自己` 的行并带 `member`（显示名，没有时用邮箱），用量卡片可切换“我自己 / 各成员”。成员用自己连接的调用不给主账号看。
