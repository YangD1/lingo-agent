# 0034 · 用量看板与租户自填单价

- **状态**：已采纳（2026-10-13，任务 69；Q69a–f 由用户确认，全部按推荐）
- **日期**：2026-10-13
- **影响**：**修订 ADR 0005 §A**“不记价格、只记 token”：仍不内置任何价格，但租户可以自己填单价，填了才显示估算费用。新增 `model_prices` 表、`tenants.price_currency` 列、`GET /tenant/usage/dashboard`、`GET / PUT /tenant/prices`、`GET /me/usage`。

## 背景
- `GET /tenant/usage`（ADR 0005，P0）只按 UTC 天 × 成员 × 连接 × 模型汇总调用、token、字符、错误、后备、平均耗时，设置页是一张表。PLAN 把图表留到了 P4。
- 看不到的东西：
  - 钱花在哪个用途上：不分 `task`，也不分前台（学习者在等）和后台（ADR 0025）。
  - 转写、发音评测、实时通话按分钟计费，但 `audio_seconds` 没有汇总。
  - 花了多少钱：ADR 0005 不内置价格，理由仍然成立（厂商常改价，租户可能走中转，价格不同）。
- `features.yaml`（ADR 0014）里 28 个 task 和 25 个功能是多对多。例如 `reflect` 被对话、口语、通话、阅读共用，`exercise_generate` 被练习组的两种入口共用。一次调用没法唯一归到某个功能上。
- 学习者自己看不到自己用了多少（成员的额度用量只在 `/org/membership` 里）。

## 决定

### 1. 按“用途”分组，即 task（Q69c）
- 看板的“按用途”维度就是 `llm_usage.task`，前端显示中文名，悬停时列出 `features.yaml` 里哪些功能会用到它。`GET /usage/estimates` 已经返回功能和 task 的对应关系，前端直接用。
- 另按 `llm_usage.background` 分前台 / 后台两档。
- 不在 `features.yaml` 里另加大类：多一份要维护的映射，而且“对话”“口语”这种大类照样会共用 `reflect`。

### 2. 看板接口：服务端汇总
- `GET /tenant/usage/dashboard?days=7|30|90`（owner / admin），范围和权限同 `/tenant/usage`：本账号自己的调用 + 成员用本账号连接的调用（ADR 0031 §8）。返回：
  - 本期合计：调用、输入 / 输出 token、字符、音频分钟、错误率、后备率、估算费用。
  - 按天序列：每天的调用、token、费用；范围内没有调用的天补 0。
  - 三个分组：按用途（task，带前台 / 后台）、按模型（连接 + 模型）、按成员（本账号自己 + 每个成员）。
- 服务端汇总，不把明细行全发给前端再算：90 天的明细是“天 × 成员 × 连接 × 模型 × task”，可能上千行，而且费用计算要放在后端统一测试。
- 旧的 `/tenant/usage` 保留，作为看板下面的“明细”表。
- 天仍按 UTC 划分（Q69e），和现有用量表、后台每日上限（ADR 0025）、成员额度（ADR 0031）一致。

### 3. 单价：租户自填，不内置（Q69a、Q69d）
- `model_prices`：每行是租户 + 连接名 + 模型，有四个可空的单价：输入每百万 token、输出每百万 token、每千字符、每分钟。键用连接名而不是连接 id，和 `llm_usage.connection_name` 对齐；连接删了重建、同名时价格还在。
- `tenants.price_currency`：一个租户一个币种，`CNY` 或 `USD`，默认 `CNY`。只用来显示，不换算。
- 不存价格历史：改价后按新价回算整个范围。看板是“大概花了多少”的估算，不是账单；存生效日期会让编辑界面和计算都复杂很多，收益小。
- 费用 = 输入 token × 输入单价 + 输出 token × 输出单价 + 字符 × 字符单价 + 音频分钟 × 每分钟单价。哪项用量大于 0 但没填对应单价，那部分就不算，结果标“部分估算”。一个模型的四项单价都没填就当作没定价。所有调用都没定价时，看板不显示费用。
- 编辑界面只列出本期出现过的“连接:模型”。
- 单价不是密钥，明文存。

### 4. 成员看到什么
- 主账号的看板里，“按成员”这一组显示每个成员用本账号连接的用量和按本账号单价算的费用。成员用自己连接的调用不算本账号的钱，主账号看不到（沿用 ADR 0031 §8）。
- `GET /me/usage`（任何登录用户）：本人本月（UTC）按能力（ADR 0031 §4 的五项：文本 token、朗读字符、转写 / 发音评测 / 通话分钟）的用量，包括本人租户的调用和用主账号连接的调用。如果是成员，附上每项能力的额度和剩余（复用 `org/usage.membership_use`）。**不含费用**：费用只给付钱的账号看（Q69f）。
- 学习者模型页 `/learner` 加“我的 AI 用量”卡（Q69f）。

## 取舍
- 不存价格历史：厂商降价后，旧月份的费用会按新价显示偏低。看板标明“按当前单价估算”。
- 按 task 分组时，不同功能共用的 task（如 `reflect`）只显示一行，看不出对话和口语各占多少。要拆的话得在每次调用里记功能名，`llm_usage` 要加列，40 多处调用都要改；现在的粒度已经够看出钱花在哪里。
- 汇总直接查 `llm_usage`，不建汇总表。90 天、单租户的量（每个学习者一天几百行）走 `(tenant_id, created_at)` 索引就够了，部署规模变大以后再加物化汇总。
