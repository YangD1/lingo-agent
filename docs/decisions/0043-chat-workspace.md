# 0043 · 对话工作区：对话页右侧打开精读 / 写作文档

- **状态**：已采纳（2026-10-15，任务 83；Q83a–h 全部按推荐确认）
- **日期**：2026-10-15
- **影响**：对话页 `/chat` 可在右侧打开工作区，左侧收窄；新增 `workspace_docs`、`workspace_doc_versions`、`workspace_annotations`、`workspace_edits` 四张表（随会话删除），助手卡片新增 `workspace`、`workspace_edit` 两种；新增工作区接口；助手新增工具 `open_workspace`、`propose_edit`；新增用量功能 `workspace_translate`、`workspace_analyze`；前端新增依赖 `react-resizable-panels`、`diff`。

## 背景
- 对话是一条往下滚的流，长文和作文放进去就被后面的消息冲走了，没法一边看原文一边问。Claude Artifacts、ChatGPT Canvas 都是“左边对话、右边文档”的布局。
- 已有的相关能力分散在独立页面：`/reading/[id]` 有查词气泡、跟读、分级版本，从文章开的对话会把原文交给 reading_coach（`chat/reading.py`）；`/writing/[id]` 有逐句批改；自由对话里发作文会走 writing_coach 批改并出卡片（`chat/writing.py`）。
- 对话页现在是三栏：应用侧栏（在 `/chat` 默认收起成图标栏，`app-sidebar.tsx`）、会话列表、对话列（`chat-app.tsx` → `TutorPanel`）。

## 决定

### 1. 范围（Q83a、Q83d）
- 第一版做通用框架（布局、文档存储和版本、打开 / 改稿工具）加两种文档：**精读**（`reading`）和**写作**（`writing`）。练习、语法讲解、表达对比、笔记以后作为新的文档类型加入，不在本次范围。
- `/reading`、`/writing` 独立页面保留，工作区复用它们的组件（`WordPopup`、跟读、批改标注）。独立页面用来系统地学，工作区用来边聊边学。
- 工作区只在对话页打开。看板和入学测结果页的对话框、桌宠小窗太窄，只显示“在对话页打开”的链接。

### 2. 布局
- **桌面（≥1024px）**：打开工作区时会话列表隐藏（应用侧栏在 `/chat` 本来就收起），对话列和工作区之间有可拖动的分隔条（`react-resizable-panels`）。对话列默认约 420px，最小 360px；工作区最小 480px。拖出来的比例存 localStorage（只是个人偏好，丢了用默认值）。工作区顶栏有标题、文档切换、版本、全屏（暂时隐藏对话列）、关闭。
- **768–1023px**：工作区覆盖对话列，顶栏有“回到对话”。
- **手机**：工作区全屏，顶部两个标签“对话 / 工作区”切换。
- 打开的文档写在 URL `?c=<会话>&w=<文档>`，刷新、分享链接后状态不变。

### 3. 文档存储和版本
- `workspace_docs`：所属会话（随会话删除）、学习者、类型、标题、来源（`paste` / `article` / `writing` / `blank`，以及来源 id）、当前版本号、创建者（学习者 / 助手）。
- `workspace_doc_versions`：每个版本的内容（精读：段落数组；写作：正文）、作者（学习者 / 助手）、来源的 tool call id。学习者手动编辑停止输入 2 秒自动保存，5 分钟内的连续编辑合并成一个版本（Q83f）；助手改稿先是**待确认版本**（见 §5），学习者接受后才成为当前版本。任何时候都可以回到历史版本（回退本身也存成一个新版本，不删历史）。
- `workspace_annotations`：精读的段落翻译、句子分析的缓存，键是（文档、类型、内容哈希），文字没变就不重复调模型；文档删除时一起删除。
- 一个会话可以有多份文档（Q83e），顶栏切换；助手只看到当前打开的那份。

### 4. 精读文档
- 来源：学习者粘贴的长文（输入框粘贴超过约 800 字时提示“在工作区精读？”）、从文章开的对话（`ReadingBar`“在工作区精读”，取学习者级别的改写版本，没有就是原文：和文章页默认打开的、助手讲解时看的是同一版；对话页不知道学习者在文章页切到了哪一版）、助手 `open_workspace`。精读文档最多约 5,000 词，超出截断并提示（Q83g）。
- 三种显示：只看原文 / 原文和译文并排（窄时上下）/ 只看译文。**译文按段落、滚到哪翻到哪**，不一次翻完整篇；只看原文时，每段右侧（跟读按钮下方）有“翻译这一段”，译文出现在段落下方，等待时有加载动画；不管从哪种显示翻的，译文都存在同一份缓存里，切到对照或译文直接复用；用量功能 `workspace_translate`（task `translate`）。
- **句子分析**：点一句话，在这句下方原地展开，可同时开多句（Q83h）：主干、从句和它们的作用、难点短语、一句话中文意思。结构化输出（Pydantic），用量功能 `workspace_analyze`（新 task `sentence_analysis`；租户没单独配这个任务的路由时用默认模型）。分析只是讲解、不是练习，不过 critic；分析里出现的语法点不写证据（不让 LLM 给掌握度打分）。
- 点单词用现有 `WordPopup`（查词、加入生词本）；段落跟读复用 `ShadowingPanel`。
- **Markdown**（任务 84，Q84a–c）：粘贴的文字常是 Markdown。存储时按块切分：标题单独成块，列表 / 引用 / 表格保留换行，代码块（围栏）连空行原样保留，普通段落的折行合并；原文和译文都按 Markdown 渲染（标题、列表、粗斜体、链接、表格、代码），单词照常可点。**代码块不翻译**（不调模型，原样返回）、不查词、不分析、不跟读；**表格整块翻译**，译文提示词要求保留所有 Markdown 标记和换行，所以译文仍渲染成表格。点句分析时保留块结构（标题、列表项、引用），句子里的行内格式暂不显示；分析和翻译用去掉标记的纯文字。已存的旧文档（换行已被合并）不迁移，重新粘贴即可。
- **选中文字 →“问 {助手名}”**：选中的句子作为 Markdown 引用块（`> …`，最多约 600 字）放进输入框，就是学习者消息的一部分：对话里照常显示，之后几轮助手也看得到，不需要单独的引用字段。

### 5. 写作文档和助手改稿（Q83c）
- 来源：空白新建、学习者发的作文（writing_coach 批改卡片上“在工作区改稿”）。同一篇文章或作文在一段对话里已经有文档时，再点就打开那份，不重复建、助手 `open_workspace`。
- 学习者直接在右侧编辑。“批改”按钮走现有写作批改（`writing/service.py`，`conversation_id` 带上），批改意见标在原文对应位置，复用 `/writing/[id]` 的标注；证据、生词照旧写入。
- **助手改稿不直接覆盖**：工具 `propose_edit` 给出若干处 `{原文片段, 改成, 理由}`，代码在当前版本里精确定位（找不到、出现不止一次或和前一处重叠的作为错误交回模型，其余照常），存成一条待确认的改稿（`workspace_edits`），回复下出一张“提了 N 处修改”的小卡片，点开定位到工作区。右侧逐处显示差异（`diff` 按词比较），每处可接受 / 拒绝，也可全部接受；确认后成为新版本，可以回退。
- 学习者在待确认期间又改了正文：已经对不上的那几处标为失效，其余仍可接受。

### 6. 助手的工具和上下文（ADR 0013）
- `open_workspace`：参数 `kind`（`reading` / `writing`）、`source`（`last_message` = 学习者这一轮或上一轮发的长文 / `article` = 这段对话的文章 / `blank`）、`title`。**不让模型在参数里抄全文**（省 token，也不会抄错）。前端收到卡片后自动在右侧打开（Q83b），回复下的卡片可“关闭”；撤销 = 删除这份文档。
- `propose_edit`：参数 `doc_id`、`edits`（最多 20 处，每处原文 ≤ 300 字）。只能改本会话、本学习者的写作文档。
- 只有 tutor 回复的那一轮带这两个工具；reading_coach、writing_coach、grammar_coach、speaking_coach 本来就不带工具。阅读会话的工作区由 `ReadingBar` 打开，作文由批改卡片打开。
- 身份不进参数，由 `cards/runtime.py` 绑定学习者和会话；同一 tool call id 只建一次文档 / 一个待确认版本（幂等）；参数不合法、文档不属于本会话等作为工具结果返回，不中断这一轮；循环上限沿用现有设置。
- **每轮上下文**：前端每次发送带上当前打开的文档 id（`workspace_doc_id`，必须属于这段会话，否则 404）；文档的类型、标题、id、版本和前 1,500 词（写作同样上限）放进系统提示（`prompts/workspace_context.md`），用 `<workspace_doc>` 标出，写明是资料不是指令；学习者引用的部分在消息本身里。所有 coach 都能看到，只有 tutor 能调工具。
- 两个工具、文档上下文、翻译和分析都写进 `docs/agent-tools.md`；“JOJO做了什么”里记一行（打开了什么文档、提了几处修改）。

## 公示（ADR 0014）
- `features.yaml` 新增 `workspace_translate`（每段约输入 300、输出 250 token）、`workspace_analyze`（约输入 400、输出 300 token）；工作区里的“翻译”开关、句子分析入口、“批改”按钮挂 `AiBadge`。助手打开文档、改稿算在 `chat_message` 的 `chat_tools` 里；带文档上下文的对话消息输入会变多，`chat_message` 的说明里注明。

## 取舍
- **自动打开 vs 先出提议卡片**：自动打开更顺手，打开文档本身不耗 token、不改学习数据，删掉就撤销了，所以不必先确认。改稿会动学习者写的东西，所以要逐处确认。
- **工具参数不带全文**：助手只说“打开哪段文字”，正文由代码从消息或文章里取，省 token 也不会抄错；代价是助手不能凭空生成长文放进工作区（第一版不需要）。
- **译文按段落懒加载**：长文整篇翻译一次几千 token，很多段学习者不需要译文；按段翻、缓存，切回原文不再调用。
- **两个新前端依赖**：`react-resizable-panels` 约 10KB（shadcn `Resizable` 的底层）、`diff` 约 20KB，都只在对话页工作区里按需加载，不影响服务端内存。
